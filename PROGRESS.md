## What exists

Built: T01–T22, T27–T48 and T43's follow-ups. Older entries are in [docs/progress-archive.md](docs/progress-archive.md); code layout in [docs/architecture.md](docs/architecture.md).

- **Tooling and CI**: monorepo (`daemon/`, `desktop/`, `templates/`, `docs/`), `justfile` (`install`, `lint`, `test`, `dev`), CI split into lint, daemon, frontend and Rust workflows with path filters (daemon tests and Rust on Linux, macOS and Windows); ruff, mypy strict, import-linter, ESLint boundaries, 500-line limit, 85% daemon coverage.
- **Core** (`core/`): config from `config.toml` and `SPOOLHQ_*`, bearer token, JSON logs, single-instance lock, ticket ids and `slugify`, the agent environment allowlist.
- **Projects** (`services/projects/`): workspaces under `~/spoolhq-projects/`, `project.yaml` validated by Pydantic (stack commands optional), invalid settings reported per project.
- **Creation** (`services/creation/`): a job that creates a project from a built-in template, an existing repo or an empty repo (workspace → repo → check commands → initial commit), refuses unsafe paths first and rolls back only what it created; an existing repo's commands run in a temporary worktree of `HEAD`, never in the checkout, and `POST /api/repos/inspect` reads its branch, state, GitHub origin, commands (justfile, Makefile, `package.json`, uv `pyproject.toml`), agent settings and missing notes files without running anything; `spool init` and `POST /api/projects` share it (only `spool init` takes folder or git URL templates, `--template-ref` and `--branch`); a project held by a running job is reported as `creating`, one whose rollback left paths as `cleanup_failed` (until dismissed).
- **Tickets** (`services/tickets/`): Markdown tickets with frontmatter, byte-exact round trip, `spool tickets` (`list`, `show`, `new`, `edit`, `set-status`), "Done when" parsing; tickets added by hand get the next number, never reused (files, `ticket/TNN` tags and the run log, under an OS lock shared by the CLI and the daemon; `services/scheduler/create.py`), and run without a spec.
- **Scheduler** (`services/scheduler/`): dependency graph, status transitions, `next_ready`, cycles, critical path, `spool plan check`.
- **Run log** (`services/runs/`): SQLite per workspace (schema 7), append-only events, event bus, crash recovery, integration journal, usage totals.
- **Git** (`services/git/`): one worktree per run, owned branches, no hooks or signing, squash and fast-forward integration helpers, diff stats.
- **Agents** (`services/agents/`): `claude-code-cli`, `codex-cli` and `claude-agent-sdk` backends behind `AgentRunner`, role registry, custom endpoints, a model per role (`agents.<role>.model`, else the backend's), sandbox policy, `FakeRunner`, contract suite; a repo's own agent settings are never loaded and an implementer that writes some blocks the ticket; `just dev-fake` runs the app with a dev fake runner (`spoolhq/devtools/`, no model).
- **Context pack** (`services/context/`): sandboxed Jinja2 prompts for implementer, reviewer and planner, character budget.
- **Notes** (`services/notes/`): the implementer's run note (progress entry and up to 5 decisions by area) read and cleaned; SpoolHQ alone writes `PROGRESS.md`'s managed part (newest 5, the rest archived), `DECISIONS.md`'s index and `docs/decisions/<area>.md` at merge and checks they agree; an old flat `DECISIONS.md` is converted on the first merge; an agent diff touching them goes back to the agent.
- **Gates** (`services/gates/`): install → lint → test without a shell, scrubbed environment, timeouts, failure excerpts; built-in gates on the ticket's diff: file size (`gates.max_file_lines`), the test guard (no deleted, removed, skipped or focused tests unless "Done when" names them; coverage at most 0.5 points below main's, `gates.coverage_report`) and the secret scan (added lines; path, line and pattern only).
- **Review** (`services/review/`): read-only reviewer with a fresh context and a strict JSON verdict.
- **Run loop** (`services/runloop/`): implement → commit → gates → review → integrate, `step` events and the implementer's transcript as run events, retries, pause on usage limits, cancel, recovery, merge policy, approve and reject (a new dependency in a manifest needs a person, `merge_policy.new_dependencies`), GitHub PR polling.
- **Planner** (`services/planner/`): read-only planner writing draft tickets, `plan.json` hashes, `spool plan generate|show|approve`, the plan summary and its problems (approve refuses while any exist); drafting 1 to 3 tickets from a short request as a daemon job (a `draft` run, no files written) with per-draft problems, saved together through the batch route (`spool tickets draft [--save]`).
- **Templates** (`services/templates/`, `templates/`): Copier with no trust, `spoolhq-template.yaml` contract, built-in `fastapi-react` (split notes layout; the contract check also runs the notes check; ruff `S` + `PLW1514`, its coverage report named in the contract).
- **GitHub** (`services/github/`): direct push or pull requests per project and ticket, token from env or keychain.
- **Code graph** (`services/codegraph/`): optional offline Graphify map in implementer and planner prompts; this repo's own graph is built locally, not committed.
- **Secrets** (`services/secrets/`): Anthropic, GitHub and ClickUp secrets in the OS keychain, write-only over the API; each can be tested with one read-only call to its provider.
- **API** (`api/`): REST for projects, creation jobs, tickets, spec, settings, runs, plan, agents, templates, secrets; one error format; ETags; WebSocket events with replay; the paged run history with each run's attempts summed up; a run's stored events by attempt; an attempt's gates, review and diff as typed reports.
- **CLI** (`cli/`): `spool serve`, `init`, `project`, `tickets`, `plan`, `run`, `runs`, `review`, `gates`, `prompt`, `templates`, `agents`, `worktrees`, `github`, `secrets`.
- **Desktop** (`desktop/`): Tauri 2 + React, token kept in Rust, event bridge, Home with Needs you, the New project dialog (three sources, live checklist, Fix, an existing repo's detected commands, remote and notices), Settings (also from the panel), project panel with run controls, the Spec tab, the Settings tab (each role's agent backend and model, each backend's default model and base URL, saved to `project.yaml`), and the Tickets tab with plan review and the ticket drawer (edit, run, unblock, approve or request changes, attempts and git), the Run tab's live run (header, steps, transcript, result panel) and its Gates, Review and Diff panels, with the drawer's gate and review lines, and the past-runs table with read-only replay of any attempt; **Add ticket** opens the drawer on a new ticket, written by hand or drafted by the planner from a few lines (one draft fills the form, a split shows tabs saved with **Save all**).
- **Not built yet**: tracker sync (T24; `services/tracker/` is empty), the other project settings in the app (v0.2), packaging (T23), dogfood (T25), release docs (T26).
