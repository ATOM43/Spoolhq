## What exists

Built: T01–T22, T27–T45 and T43's follow-ups. Older entries are in [docs/progress-archive.md](docs/progress-archive.md); code layout in [docs/architecture.md](docs/architecture.md).

- **Tooling and CI**: monorepo (`daemon/`, `desktop/`, `templates/`, `docs/`), `justfile` (`install`, `lint`, `test`, `dev`), CI split into lint, daemon, frontend and Rust workflows with path filters (daemon tests and Rust on Linux, macOS and Windows); ruff, mypy strict, import-linter, ESLint boundaries, 500-line limit, 85% daemon coverage.
- **Core** (`core/`): config from `config.toml` and `SPOOLHQ_*`, bearer token, JSON logs, single-instance lock, ticket ids and `slugify`, the agent environment allowlist.
- **Projects** (`services/projects/`): workspaces under `~/spoolhq-projects/`, `project.yaml` validated by Pydantic (stack commands optional), invalid settings reported per project.
- **Creation** (`services/creation/`): a job that creates a project from a built-in template, an existing repo or an empty repo (workspace → repo → check commands → initial commit), refuses unsafe paths first and rolls back only what it created; an existing repo's commands run in a temporary worktree of `HEAD`, never in the checkout, and `POST /api/repos/inspect` reads its branch, state, GitHub origin, commands (justfile, Makefile, `package.json`, uv `pyproject.toml`), agent settings and missing notes files without running anything; `spool init` and `POST /api/projects` share it (only `spool init` takes folder or git URL templates, `--template-ref` and `--branch`); a project held by a running job is reported as `creating`, one whose rollback left paths as `cleanup_failed` (until dismissed).
- **Tickets** (`services/tickets/`): Markdown tickets with frontmatter, byte-exact round trip, `spool tickets` (`list`, `show`, `new`, `edit`, `set-status`), "Done when" parsing; tickets added by hand get the next number, never reused (files, `ticket/TNN` tags and the run log, under an OS lock shared by the CLI and the daemon; `services/scheduler/create.py`), and run without a spec.
- **Scheduler** (`services/scheduler/`): dependency graph, status transitions, `next_ready`, cycles, critical path, `spool plan check`.
- **Run log** (`services/runs/`): SQLite per workspace (schema 7), append-only events, event bus, crash recovery, integration journal, usage totals.
- **Git** (`services/git/`): one worktree per run, owned branches, no hooks or signing, squash and fast-forward integration helpers, diff stats.
- **Agents** (`services/agents/`): `claude-code-cli`, `codex-cli` and `claude-agent-sdk` backends behind `AgentRunner`, role registry, custom endpoints, sandbox policy, `FakeRunner`, contract suite; a repo's own agent settings are never loaded and an implementer that writes some blocks the ticket; `just dev-fake` runs the app with a dev fake runner (`spoolhq/devtools/`, no model).
- **Context pack** (`services/context/`): sandboxed Jinja2 prompts for implementer, reviewer and planner, character budget.
- **Notes** (`services/notes/`): the implementer's run note (progress entry and up to 5 decisions by area) read and cleaned; SpoolHQ alone writes `PROGRESS.md`'s managed part (newest 5, the rest archived), `DECISIONS.md`'s index and `docs/decisions/<area>.md` at merge and checks they agree; an agent diff touching them goes back to the agent.
- **Gates** (`services/gates/`): install → lint → test without a shell, scrubbed environment, timeouts, failure excerpts.
- **Review** (`services/review/`): read-only reviewer with a fresh context and a strict JSON verdict.
- **Run loop** (`services/runloop/`): implement → commit → gates → review → integrate, `step` events and the implementer's transcript as run events, retries, pause on usage limits, cancel, recovery, merge policy, approve and reject, GitHub PR polling.
- **Planner** (`services/planner/`): read-only planner writing draft tickets, `plan.json` hashes, `spool plan generate|show|approve`, the plan summary and its problems (approve refuses while any exist); drafting 1 to 3 tickets from a short request as a daemon job (a `draft` run, no files written) with per-draft problems, saved together through the batch route (`spool tickets draft [--save]`).
- **Templates** (`services/templates/`, `templates/`): Copier with no trust, `spoolhq-template.yaml` contract, built-in `fastapi-react`.
- **GitHub** (`services/github/`): direct push or pull requests per project and ticket, token from env or keychain.
- **Code graph** (`services/codegraph/`): optional offline Graphify map in implementer and planner prompts; this repo's own graph is built locally, not committed.
- **Secrets** (`services/secrets/`): Anthropic, GitHub and ClickUp secrets in the OS keychain, write-only over the API; each can be tested with one read-only call to its provider.
- **API** (`api/`): REST for projects, creation jobs, tickets, spec, settings, runs, plan, agents, templates, secrets; one error format; ETags; WebSocket events with replay; the paged run history with each run's attempts summed up; a run's stored events by attempt; an attempt's gates, review and diff as typed reports.
- **CLI** (`cli/`): `spool serve`, `init`, `project`, `tickets`, `plan`, `run`, `runs`, `review`, `gates`, `prompt`, `templates`, `agents`, `worktrees`, `github`, `secrets`.
- **Desktop** (`desktop/`): Tauri 2 + React, token kept in Rust, event bridge, Home with Needs you, the New project dialog (three sources, live checklist, Fix, an existing repo's detected commands, remote and notices), Settings (also from the panel), project panel with run controls, the Spec tab, and the Tickets tab with plan review and the ticket drawer (edit, run, unblock, approve or request changes, attempts and git), the Run tab's live run (header, steps, transcript, result panel) and its Gates, Review and Diff panels, with the drawer's gate and review lines, and the past-runs table with read-only replay of any attempt; **Add ticket** opens the drawer on a new ticket, written by hand or drafted by the planner from a few lines (one draft fills the form, a split shows tabs saved with **Save all**).

## Windows git config race

- Cause (Windows daemon job of run 44615500626, attempt 1): `tests/cli/test_run.py::test_integrate_merges_a_held_ticket` failed with "git show-ref failed (exit 128): warning: unable to access '.git/config': Permission denied". The project load's `default_branch` check (`has_local_branch`, `git show-ref`) read `.git/config` while the resumed run's worktree teardown ran `git branch -D` on the ticket branch, which rewrites the config to drop the branch section and its SpoolHQ marker.
- `services/git/runner.py`: `run_git` holds an in-process lock per repository while git runs, keyed by `git rev-parse --git-common-dir` (cached per path; a repo and its worktrees share one lock; outside a repo the folder is the key). On Windows a call whose stderr shows git couldn't read or lock the config (`could not lock config file`, `unable to access` or `Permission denied` with `config` on the same line) is tried up to 3 times, 100 ms then 300 ms apart, logging "git config busy; retrying git <subcommand>"; any other failure returns at once.
- Tests: two threads on one repo never overlap, two repos do (a barrier), a repo, its worktree and a subfolder share one lock, each config message retried then succeeding, three failures returning the error, other failures and Linux/macOS not retried, a stress test (20 threads, 100 `branch -D` and 100 config/ref reads on one repo) on every OS.

## Copier failure test flake

- Cause: `tests/services/templates/test_generate.py::test_a_copier_failure_is_reported` asserted that `render` left no folder after a Jinja error. `render` passes `cleanup_on_error=False` (the caller cleans up), and Copier walks the template with unsorted `os.scandir`, so whether `README.md` was written before `bad.txt.jinja` failed depended on directory order: never on tmpfs (newest entry first, so it passed locally), always on btrfs (creation order, 5/5 failures), by name hash on ext4 (CI's Ubuntu). No product bug: the creation job records the repo folder before rendering and its rollback removes it (paths it can't delete go in `rollback.left`); `check_template` removes its temp folder in a `finally`.
- Tests: the broken file sits in `sub/`, which Copier always creates first (it yields folders before their contents), and the test asserts the partial output is left to the caller; new `test_job.py::test_a_copier_failure_rolls_back` runs a real job on that template and checks the repo folder and workspace are gone with nothing left over (it fails if the repo isn't recorded for rollback).
