# Decisions · Core

Config, auth, logs, layering, tooling and CI. Listed in [DECISIONS.md](../../DECISIONS.md).

1. **Name: SpoolHQ** (Python package `spoolhq`, CLI `spool`). A spool feeds thread one turn at a time, as the loop feeds tickets; `spoolhq` was free as a package name and `spool` is short to type.
3. **Separate Python daemon (FastAPI).** Runs must survive closing the window, and the same daemon can run headless on a server.
4. **CLI: Typer.** Typed, minimal-boilerplate CLI that shares code and types with the daemon.
6. **Storage: files for projects and tickets, SQLite for run history.** Specs and tickets stay readable and diffable in git; run history needs queries, not diffs.
10. **Licence: Apache-2.0.** Permissive, with an explicit patent grant, and compatible with the prior art we may borrow from.
12. **`.gitattributes` forces LF line endings.** Windows checkouts would otherwise get CRLF and fail the Prettier and ruff format checks.
13. **ruff's `S` (security) rules are on.** `shell=True` and similar unsafe calls are caught in CI rather than in review.
14. **`uv sync --locked` everywhere.** CI fails if `uv.lock` is out of date instead of silently re-resolving.
15. **The justfile's Windows shell is `powershell.exe`, not `pwsh`.** Windows PowerShell is always installed; PowerShell 7 is not.
17. **The daemon binds to 127.0.0.1 only, with no override.** It runs agents on your code; nothing off the machine should reach it. A non-loopback `host` in config or env is a validation error.
18. **Local auth is a bearer token in `~/.spoolhq/token` (mode 0600, folder 0700).** Other local users and web pages cannot read it, and the CLI and desktop app need no login; it is compared with `secrets.compare_digest`.
19. **`GET /api/health` needs no token.** Clients use it to detect a running daemon, and it reveals nothing; every other `/api/*` route is protected by a middleware, so new routes are protected by default.
20. **Requests whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>` get 400.** This blocks DNS-rebinding attacks from web pages, which send their own domain in `Host`.
21. **Logs are JSON lines from stdlib `logging` with a small formatter, no logging dependency.** One rotating file (10 MB × 5) that tools can parse; the token is redacted from every line as a backstop.
22. **Runtime dependencies are pinned exactly in `pyproject.toml`, like the dev tools.** SpoolHQ is an application, not a library; revisit if it is ever installed alongside other packages.
34. **Backend layering: `core` → `services` → `api`/`cli`, enforced by import-linter.** Routers and commands stay thin and call services; services never import FastAPI, Starlette, Typer or uvicorn, so the same logic serves HTTP, the CLI and tests; `core` (config, token, logging) depends on nothing above it. The contracts live in `daemon/pyproject.toml` and run in `just lint`, so a wrong import fails CI.
36. **`core/logs.py` keeps its name** rather than becoming `core/logging.py`, so it never shadows the standard library's `logging` module.
44. **85% line-coverage floor on the daemon, enforced in CI** (`--cov-fail-under=85` in `just test`), to be raised as the code grows. Only `if TYPE_CHECKING:` blocks are excluded; the desktop app reports coverage with no threshold yet.
58. **CLI forces UTF-8 on stdout/stderr.** Messages keep their arrows (`blocked → done`, `T01 → T02 → T01`), but on Windows a redirected stream (`spool plan check > out.txt`) falls back to the console code page, such as cp1252, which cannot encode `→`, so the command crashed. The `spool` entry point (`cli.main:main`, also behind `python -m spoolhq`) reconfigures both streams to UTF-8 before Typer runs, keeping each stream's `errors` setting, so output is the same bytes on every OS. No ASCII fallback.
79. **The ticket id pattern moved to `core/ids.py`.** `services/git` needs it for branch names and paths but may not import `services/tickets` (which imports `services/projects`, which imports `services/git`); `services/tickets` and `services/runs` import it from there too, so there is still one pattern.
87. **Daemon tests mirror the source layout.** `tests/core/`, `tests/api/`, `tests/cli/` and `tests/services/<domain>/`, with the folder name dropped from file names (`tests/cli/test_plan.py`). Every test folder, `tests/` included, is a package (empty `__init__.py`) so same-named files in different folders don't collide, under pytest's default `prepend` import mode; shared helpers are imported as `tests.conftest`. Fixtures used by one folder live in its `conftest.py` (only `wt_repo`, `wt_root` and `manager`, in `services/git/`); everything used by more than one folder, and the autouse `home`/`projects_dir`, stays in `tests/conftest.py`, which also exports `FIXTURES_DIR` for the shared `tests/fixtures/` data. Integration tests stay marker-based, not in a folder. `tests/test_layout.py` enforces the layout; `test_version.py` went to `core/` because it checks the package's own `__version__`, not the CLI.
125. **`spool serve` has no `--port` option;** the port comes from `SPOOLHQ_PORT` or `config.toml`. The CLI client reads the port from the settings, so a daemon started on another port with the flag was one `spool` couldn't reach.
126. **Shared helpers have one copy:** `check_ticket_id` and `id_key` in `core/ids.py`, `READ_ONLY_GIT` in `core/agent_policy.py` (replacing the copy and equality test of 115), the YAML setup and `to_plain` in `services/projects/yaml_io.py` (the tickets version, which also turns ruamel's scalar subclasses into plain values), and `hours` in `cli/common.py`. The ticket model's `id` validator keeps its own regex check, because its message (`id: must be T followed by 2 or 3 digits, like T04`) differs from `check_ticket_id`'s and is part of the validation output.
127. **No source file over 500 lines.** `just lint` runs `scripts/check_line_limit.py` (standard library only) over `daemon/src/spoolhq/**/*.py` and `desktop/src/**/*.{ts,tsx}`; tests (`daemon/tests/`, and `*.test.*` / `*.spec.*` next to the desktop code) are exempt. Exceptions go in its `ALLOWED` table with a reason; it is empty. Two files were over: `services/agents/claude_cli.py` (674) lost the command line, settings, environment, stub clean-up and worktree check to `claude_config.py`, keeping detection and process handling; `services/runs/log.py` (533) lost the column lists, row conversion, `fetch_run` and payload encoding to `rows.py`, keeping `RunLog` and its transaction. Package exports are unchanged; the config tests moved with their code to `test_claude_config.py`.
199. **SpoolHQ's own `.gitignore` ignores `.pnpm-store/`.**
283. **Starlette's `TestClient` answers with `httpx2` once it is installed** (T31). The SDK pulls in mcp 2.3.0, which depends on `httpx2`; Starlette 1.8's test client prefers it, so `tests/cli/test_run.py`'s forwarding handler handed an `httpx2.Response` to an `httpx.MockTransport`. The handler now rebuilds an `httpx.Response`; no runtime code uses the test client.
314. **The frontend file-length limit already existed** (T32 step 0). `scripts/check_line_limit.py` (run by `just lint`) checks `desktop/src/**/*.ts(x)` at 500 lines, blank lines and comments counted, tests (`.test.`/`.spec.`) exempt, `schema.gen.ts` allowed. It was kept as it is, and no ESLint `max-lines` was added. No file was over the limit.
330. **Agent docs are split: an index plus area files** (Docs split chore, 2026-11-05). `DECISIONS.md` lists `NNN · title · area file`; entries live in `docs/decisions/<area>.md`, in one area each. `PROGRESS.md` keeps a "What exists" summary and the last 5 entries; older entries are in `docs/progress-archive.md`. Agents read the summary, the index and only the area files their ticket touches, instead of 329 entries every session. `scripts/check_decisions.py` keeps the index and the area files in step. The context pack still reads the repo's `DECISIONS.md` (now index lines) and the newest `PROGRESS.md` entries; the summary sits above them, so it isn't one of the newest.
336. **`PLW1514` is on, and `just lint` checks `scripts/`** (T34). ruff 0.17 has `unspecified-encoding` only as a preview rule, so `[tool.ruff.lint]` sets `preview = true` with `explicit-preview-rules = true`: only preview rules named in `select` (just `PLW1514`) are enabled, and no other rule changes. `ruff check` and `ruff format --check` now also run on `../scripts`, which picks up `daemon/pyproject.toml`. There were no findings (the Windows UTF-8 fix in c6ea373 had passed `encoding="utf-8"` everywhere), so no file changed.
358. **Rust files are under the 500-line limit, and Clippy denies long functions** (T21). `scripts/check_line_limit.py` checks `desktop/src-tauri/src/**/*.rs`, counting whole files (Rust tests sit inline in `mod tests`, so there is nothing to exempt); `oversized(root)` takes the repo root so a fixture can test it. `Cargo.toml`'s `[lints.clippy]` turns on only `too_many_lines` (pedantic, default 100 lines) at `warn`, which `just lint`'s `-D warnings` makes fatal. No file or function was over, so nothing was split.
395. **CI is four workflows; lint and the Vitest tests run on Linux only** (Faster CI chore, 2026-11-19). `lint.yml`, `daemon.yml`, `frontend.yml` and `rust.yml` run side by side, each with its own `paths` filter and a `concurrency` group per workflow and branch (a group shared by all four would let one workflow cancel another). Lint (ruff, mypy, import-linter, line limits, decisions, the docs-reading daemon tests, ESLint, Prettier, tsc, the API-client check) gives the same answer on every OS, and Vitest runs in jsdom, so both run once on Linux; the daemon tests and the Rust checks (fmt, Clippy, `cargo test`, a debug build) touch the file system, processes and the toolchain and stay on Linux, macOS and Windows. A docs or Markdown change runs only lint; `justfile`, workflows, lockfiles and `scripts/` run everything. The justfile splits `lint`, `test` and `install` into `-daemon`, `-desktop` and `-rust` parts the jobs call, so local and CI commands stay the same. A full run took about 31 minutes, 17 of them the daemon tests on Windows.
396. **CI installs `just` from the `rust-just` wheel on PyPI** (Faster CI chore). `extractions/setup-just` downloads a GitHub release, which failed twice with HTTP 504. `uv tool install rust-just==1.59.0` after `astral-sh/setup-uv` is pinned, comes from PyPI's CDN and is kept in the uv cache, whose key includes the workflow file, so changing the pin refreshes it. No new action.
397. **Daemon tests run in parallel with pytest-xdist** (Faster CI chore). The suite took 17 min on Windows, 8 on macOS and 4 on Linux, over the 4-minute bar. `pytest-xdist==3.8.0` with `-n auto` in `just test-daemon` (pytest-cov combines the workers' coverage); the full suite passed three times in a row locally under it, in about 43 s each. `just t` and the lint job's few tests run serially.
419. **SpoolHQ's lint caps PROGRESS.md at 5 recent entries** (T46). `scripts/check_decisions.py` counts PROGRESS.md as it is written today: every `## ` heading except `## What exists` is a recent entry (the entries are `## <title>` sections under the summary; the file has no `spoolhq:recent` markers yet). `### ` entries SpoolHQ would add between markers aren't counted: SpoolHQ keeps those at 5 itself (decision 413). More than 5 fails with "PROGRESS.md has 7 recent entries; move the oldest to docs/progress-archive.md". It stays in the same script so `just lint` gains no step.
450. **The daemon is packaged with PyInstaller as one file named `spoolhq-<target triple>`** (T23). `pyinstaller==6.22.3` sits in its own `build` dependency group, so `just install` and CI's test jobs don't install it. One file because Tauri's `externalBin` takes files, not folders; the name is Tauri's sidecar convention, and `scripts/build_sidecar.py` maps the triple from `platform` rather than asking `rustc`, so the package job needs no Rust. No `--collect-submodules=spoolhq`: PyInstaller follows imports inside functions anyway, and collecting would hidden-import `spoolhq.devtools` against the exclude. Copier's default extension `jinja2_ansible_filters` is a hidden import: Copier loads it by name and every template failed without it. The SDK's bundled Claude Code (315 MB) stays out; the packaged backend uses `claude` on `PATH`.
451. **The dev-tools check reads the built binary** (T23). After building, the script lists the binary with PyInstaller's archive viewer (`--list --recursive --brief`) and fails on any entry naming `spoolhq.devtools` or `spoolhq/devtools`, and if the list doesn't hold `spoolhq.cli.main` (an unreadable listing must not pass). Reading the binary checks what ships, not what the analysis meant to include.
452. **The Rust job builds against an empty sidecar placeholder** (T23). `tauri-build` refuses to build when an `externalBin` file is missing, even for clippy and tests. `just sidecar-placeholder` (the build script's `--placeholder`) creates an empty file only if none exists, so it never replaces a real binary; the Rust workflow runs it before linting. Not done in `build.rs`, so a release build can't silently ship a placeholder. An app built with it shows the daemon-missing state.
462. **`config.toml` is edited line by line, and refused when that isn't safe** (T49). The daemon had no TOML writer and adding one for one boolean wasn't worth a dependency. `core/config_file.py` `set_bool` replaces the key's line in its `[table]`, or adds the line or the table, keeps every other line and comment, parses the result with `tomllib` and writes it atomically only if the key reads back as the value. A key set another way (an inline table, a dotted key) or a file that isn't valid TOML is left untouched and the route answers 409 `config_not_saved`.
467. **One app version in three files, set by `just set-version`** (T50). The daemon's `pyproject.toml`, `desktop/package.json` and `tauri.conf.json` (which names the bundles and the updater compares against) carry the same version; `Cargo.toml` stays 0.0.0, as Tauri takes the app's version from `tauri.conf.json`. `scripts/release.py set-version` rewrites only each file's first `version` line, so formatting and comments survive, and the recipe then runs `uv lock` because `uv.lock` records the package's own version and `--locked` would fail. `check-tag` fails a release when the files disagree or the tag isn't `v<version>`, with fixed messages unit-tested in `tests/test_layout.py`.
468. **`latest.json` is built by `scripts/release.py`, not `tauri-action`** (T50). The feed is a few lines of JSON from the `.sig` files, and building it ourselves keeps the release to the actions we already pin, plus `upload-artifact` 7.0.2 and `download-artifact` 8.0.2 to carry each OS's bundles to the publishing job. Each OS writes `latest-<platform>.json` (the macOS update artifacts are renamed by architecture, since both are `SpoolHQ.app.tar.gz`); the last job merges them. `check-feed` also compares each signature's minisign key id with the public key, so a release signed with the wrong key fails rather than shipping updates every install refuses. The notes are the tag's annotation, re-fetched because `actions/checkout` drops it. A tag makes a draft release; the user publishes it, and only that job has `contents: write`.
