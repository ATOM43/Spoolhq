# Decisions · Agents

Agent backends, policy and sandbox, usage and budgets. Listed in [DECISIONS.md](../../DECISIONS.md).

5. **Agent runtime: Claude Agent SDK behind an `AgentRunner` interface.** Use the best-supported coding agent now, without locking out other agents later.
8. **Only the planner, implementer and reviewer are LLM agents; everything else is plain code.** Gates, git, merging and tracker sync must be deterministic and testable.
88. **The agent policy is enforced by Claude Code, in four layers; SpoolHQ builds the configuration and verifies it took effect.** (1) `--restricted` confines the file tools to the worktree and ignores repository settings and hooks; (2) `--permission-mode dontAsk` with `--permission-prompts none` and an explicit allowlist; (3) the OS sandbox, with no network and the credential files denied; (4) a scrubbed environment. SpoolHQ never passes `--dangerously-skip-permissions` or `bypassPermissions`; a test fails if either string appears in `services/agents/` outside comments and docstrings. Writing our own enforcement (a path hook, a command parser) would be weaker than the OS sandbox and would have to track every Claude Code change.
89. **The allowlist is the project's stack commands plus read-only git, two rules per command.** Every command in `project.yaml`'s `commands` (`install`, `lint`, `test` and any others) and `git status`, `git diff`, `git log`, `git show` become `Bash(<cmd>)` (exact) and `Bash(<cmd> *)` (prefix). A stack command containing `; & | < > $ ` ( ) * ? [ ] { } \`, a newline, or leading or trailing spaces is refused with `PolicyError` naming the field, because it would widen the rules. The file tools `Read`, `Edit`, `Write`, `Glob` and `Grep` are allowed as a whole, since `--restricted` already confines them to the worktree.
90. **The OS sandbox is required.** The agent writes the tests that `just test` runs, so the allowlist alone is no boundary; the sandbox is. Native Windows, where Claude Code has no sandbox, is refused with a message pointing to WSL2; Linux without `bwrap` or `socat` is refused with an install hint (`sudo dnf install bubblewrap socat` on Fedora); `failIfUnavailable: true` makes Claude Code refuse rather than run unsandboxed, and `autoAllowBashIfSandboxed: false` stops it approving sandboxed commands that aren't on the allowlist.
91. **No network for the agent's commands in v1** (`allowedDomains: []`, `strictAllowlist: true`). Installs run in the gates, as code, outside the agent.
92. **Sandboxed commands may not read the usual credential files or the SpoolHQ home:** `~/.ssh`, `~/.aws`, `~/.config/gh`, `~/.gnupg`, `~/.netrc`, `~/.docker/config.json`, `~/.kube`, `~/.git-credentials`, `~/.config/git/credentials`, `~/.npmrc`, `~/.pypirc`, `~/.local/share/keyrings`, and the SpoolHQ home, which holds the API token. Worktrees live inside the home by default (`<home>/worktrees/…`), where denying the whole folder would deny the worktree itself; then the list has the token file plus every entry of the home except the folders on the way down to the worktree.
93. **The `claude` process gets only an allowlisted environment.** `PATH`, `HOME`, user, locale, temp, XDG, D-Bus, `CLAUDE_CONFIG_DIR` and proxy variables (and Windows' system variables), plus `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` and `DISABLE_AUTOUPDATER=1`. `ANTHROPIC_API_KEY` is passed only for API billing: with it in the environment Claude Code bills the API instead of the subscription. `detect()` therefore asks `claude auth status` without the key first, and offers it only when there is no subscription login, so a subscription always wins.
94. **The prompt goes on stdin, never as an argument.** It isn't visible in the process list, isn't limited by command-line length (Claude Code caps stdin at 10 MB; a larger prompt raises `ValueError`) and can never be read as a flag. Ticket and prompt text are untrusted and never reach argv or rules.
95. **A usage limit is an outcome, not a failure.** The runner returns `usage_limited` with `reset_at` (from a rejected `rate_limit_event`'s `rate_limit_info.resetsAt`, or the epoch after `usage limit…|` in the error, else `None`) and no error; T13 turns it into a paused run.
96. **Cost and tokens.** Subscription runs report tokens and `cost_micro_usd=None` (Claude Code's own estimate is ignored); API-key runs report `total_cost_usd` as integer micro-USD via `Decimal`, as the run log stores it (63). `input_tokens` counts uncached input, cache writes and cache reads, because with prompt caching uncached input is a handful of tokens per turn and a token budget on it alone would never trip; `Usage` events keep the breakdown, and assistant usage is counted once per message id.
97. **Claude Code 2.1.259 or newer.** `--permission-prompts` (needed so denials are final and reported) first shipped there; an older CLI is refused with `Claude Code 2.1.200 is too old; SpoolHQ needs 2.1.259 or newer (run: claude update)`.
98. **The adapter also accepts the `default` permission mode in `init`.** With `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, Claude Code 2.1.302 prints `Permission mode forced to default — CLAUDE_CODE_SUBPROCESS_ENV_SCRUB is set` and reports `permissionMode: "default"`, whatever `--permission-mode`, `--allowedTools` or settings say (checked on 18 Oct 2026). Dropping the scrub would leave `ANTHROPIC_API_KEY` in the environment of every command an API-billed agent runs; keeping `dontAsk` strictly would stop every run. With `--permission-prompts none`, `default` denies everything that isn't pre-approved, as `dontAsk` does (the real run shows the python call denied and the allowlisted write allowed), so the adapter accepts `dontAsk` or `default` and stops on any other mode. The parser's own default stays `dontAsk` only, and the fake runner uses the adapter's set.
99. **The `init` message is checked before anything else is believed.** Any tool not requested (anything outside `--tools`, any `mcp__*`, `WebFetch`, `WebSearch`), an unexpected permission mode, or an assistant, user or result message before `init` raises `PolicyViolation`; the adapter stops the process and returns `error` with `policy not enforced: …`.
100. **`Glob` and `Grep` are in `--tools` and `--allowedTools`, and the settings include `disableAllHooks: true`.** Claude Code 2.1.302 accepts and reports both tools in a real run; `disableAllHooks` is a documented setting. It is redundant with `--restricted` (which already skips repository settings and their hooks) but costs nothing.
101. **`FileEdit` comes from a successful tool result, not the tool call.** An `Edit` or `Write` counts once its `tool_result` arrives without `is_error` and only if its path resolves inside the worktree; a denied or failed edit is not in `files_changed`, and one outside the worktree is logged as a warning.
102. **A worktree must not contain the user's home, the SpoolHQ home or a denied path, or sit inside one.** Sandboxed commands may write anywhere in the worktree, so such a worktree would let them write `~/.ssh/authorized_keys` or the token; `AgentPolicy.for_worktree` and `ClaudeCliRunner.run` refuse it with `PolicyError`.
103. **`ClaudeCliRunner`'s `platform` parameter only changes `detect()`'s sandbox rules.** The environment allowlist and process handling (process groups, signals) always follow the OS the daemon runs on, so tests can pretend to be Linux on the Windows runner and still start a working Python.
104. **SpoolHQ cleans up after Claude Code's env scrub.** With `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, Claude Code 2.1.302 creates 19 empty placeholders in its working folder (`.env*`, `package.json`, lockfiles, `.npmrc`, `.claude/agents/`, `node_modules/.bin/`, …) and leaves them, even for `claude auth status`; without the variable it creates none (checked on 18 Oct 2026). Left alone they would land in every ticket's diff, and `spool agents` would drop them wherever it is run. So `detect()` runs its probes in a throwaway temp folder, and after a run the adapter removes each placeholder that wasn't in the worktree before the run and is still empty (a folder only if it holds no files). The scrub itself stays (93, 98).
118. **Supersedes 5: agents run through the Claude Code CLI (see 88),** not the Claude Agent SDK. The `AgentRunner` interface stays, so other agents can still be added.
120. **Claude Code's own files are denied to sandboxed commands:** `~/.claude` and `~/.claude.json` join the credential list (92), and the `CLAUDE_CONFIG_DIR` folder is added when that variable is set in the environment passed to `claude`. They hold Claude Code's login and session history. Only the agent's commands are denied; Claude Code itself still reads them. The adapter adds the `CLAUDE_CONFIG_DIR` folder to the policy before the worktree check, so a worktree inside it is refused like one inside any other denied path (102).
123. **`RunResult.summary` keeps the end of the agent's final message,** the last 4,000 characters after a `[… N characters cut …]` line, instead of the beginning: the `<progress>` block the context package reads is at the end (111).
124. **The `claude` environment also passes the lower-case proxy variables, `NODE_EXTRA_CA_CERTS` and `SSL_CERT_FILE`** (extends 93). Behind a corporate proxy with its own CA, Claude Code could not reach the API without them; none of them is a secret.
151. **`FakeRunner` accepts a sequence of transcripts** and replays the next one on each `run()`; a run past the end raises `RuntimeError`. A single path is still replayed on every run. `calls` records each run's prompt and policy, so tests can check what a retry was sent.
172. **Init permission mode `default` is accepted only when it is really safe** (T09 follow-up): `permission_modes(env, argv)` allows it only when `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` is in the environment actually passed to `claude` and `--permission-prompts none` is on its command line; otherwise only `dontAsk`. `FakeRunner` checks with the environment and flag the adapter always passes.
195. **The implementer may not run the project's `install` command** (amends 89). In M1 the agent ran `just install` inside its sandbox, where pnpm couldn't use its global store and created `.pnpm-store/` in the worktree, which was committed with a symlink in it. Installs belong to the gates, outside the sandbox (91). `Commands.for_implementer()` (all commands but `install`) feeds both the implementer's policy and its prompt, so the prompt doesn't list a command the agent would be denied. `spool prompt show` uses it too. The reviewer's policy is unchanged.
202. **The per-ticket token budget counts weighted tokens**: input + output + cache writes + cache reads × 0.1 (`core/tokens.py`, floor division). Cache reads cost a tenth of fresh input, and every turn re-reads the whole context, so raw counting made a 1M budget last about 20 turns. T29's implementer made 34 calls for about 2.2M raw tokens, 2.1M of them cache reads: about 300k weighted. The run log keeps the raw numbers and adds `attempts.cache_read_tokens` (schema version 4); `spool runs list` and `spool runs show` print the weighted total next to them. `spool run status` still shows raw tokens.
205. **`npm_config_verify_deps_before_run=false` is in `ENV_SET`.** pnpm otherwise tries to install from the network before each `pnpm run`, which fails in the sandbox and adds noise; the gates' install provides the deps. `ENV_SET` goes to every `claude` process, so the reviewer gets it too; it can't run commands, so that changes nothing for it.
257. **Roles resolve through a backend registry** (T27). `services/agents/backends.py` maps names to factories `factory(base_url, model)`; only `claude-code-cli` is built in and tests add fakes (the `fake_backend` fixture patches the dict). `project.yaml` validates `agents.default`, `planner`, `implementer`, `reviewer` and the keys of `agents.backends` against it, so `codex-cli`, `gemini-cli` and `claude-agent-sdk` (accepted by T04's `Literal`, never runnable) are now refused until T30/T31 register them. This reconciles T15's `agents.planner` (DECISIONS 206): the run loop's `Agents` holder stays, but the daemon no longer passes fixed runners; `Agents.for_project` builds each run's runners from the project, and `PlanJobs` the planner's when a plan starts. Fixed `Agents` remain for tests. `spool plan generate` and `spool review` use the project's roles too.
258. **`services/projects` imports `services/agents`** for the registry, so `services.templates` reaches agents through projects; its import contract no longer forbids agents, like the planner's contract already allows gates and git.
259. **Custom endpoints: `agents.backends.<name>.base_url` and `.model`** (T27). `base_url` must be http(s), plain http only for `localhost`, `127.0.0.1`, `::1`, with no username or password (`urlsplit`, bad ports refused). For Claude Code `base_url` becomes `ANTHROPIC_BASE_URL` in that child's environment and `model` becomes `--model` (https://code.claude.com/docs/en/env-vars: "`--model` and `/model` override `ANTHROPIC_MODEL`"). The daemon's own `ANTHROPIC_BASE_URL` stays off the allowlist; nothing is written to the user's Claude config. A `model` passed to `run()` still wins over the configured one (no caller passes one today). No auth token is set for the endpoint: Ollama ignores it, and passing a placeholder `ANTHROPIC_AUTH_TOKEN` would change how a subscription login behaves; left for a later ticket.
260. **One contract suite over adapter cases** (T27, `tests/services/agents/test_contract.py`). An `AdapterCase` is `make(tmp_path, scenario, hang)`; scenarios are the recorded Claude transcripts. To run timeout and cancel, `FakeRunner` gained `stall_s` (wait like a hung agent, honouring `timeout_s` and `cancel`) and checks `timeout_s` between lines; it also takes a `name`, so fakes registered as different backends can be told apart in the run log.
261. **A custom endpoint gets SpoolHQ's own token, never the subscription login** (T30 step 0, replacing the "no auth token" part of 259). With `base_url`, `services/agents/endpoint.py` supplies the credential: the fixed dummy `spoolhq-local-endpoint` for `localhost`, `127.0.0.1` and `::1`; otherwise `SPOOLHQ_ENDPOINT_TOKEN_<BACKEND>` or the keychain (`spool secrets set endpoint:<backend>`, service `spoolhq`, key `endpoint:<backend>`), and without one the backend is refused before starting (`custom endpoint <url> needs its own token; run spool secrets set endpoint:<backend>`, as `detect()`'s reason and `BackendUnavailableError`). For Claude Code the token is `ANTHROPIC_AUTH_TOKEN`: it ranks above the claude.ai login in https://code.claude.com/docs/en/authentication#authentication-precedence ("2. `ANTHROPIC_AUTH_TOKEN` environment variable. Sent as the `Authorization: Bearer` header" … "7. Subscription OAuth credentials from `/login`"), and https://code.claude.com/docs/en/llm-gateway#subscriptions-and-gateways says "Claude Code keeps a saved claude.ai login on the machine but doesn't send it with those requests", and that `ANTHROPIC_BASE_URL` alone "doesn't replace the subscription". `ANTHROPIC_API_KEY` is never passed with a `base_url`, and `detect()` skips `claude auth status` (login `endpoint token`, billing `unknown`, so no `--max-budget-usd`). The keychain lookup lives in `services/agents` because that package may not import `services/github`. Checked against Claude Code 2.1.314 docs on 2026-10-30.
262. **Codex CLI is the `codex-cli` backend, on the T09 contract** (T30). `CodexCliRunner.run()` streams the same normalised events and returns the same `RunResult`; it runs `codex exec --json` non-interactively in the worktree (cwd and `--cd`), the prompt on stdin (`-`). Checked against Codex CLI **0.166.0** (latest on npm, published 2026-10-29) and its docs on 2026-10-30: https://learn.chatgpt.com/docs/developer-commands?surface=cli (flags), https://learn.chatgpt.com/docs/non-interactive-mode (exec, `--json` events, stdin), https://learn.chatgpt.com/docs/permissions (permission profiles), https://learn.chatgpt.com/docs/sandboxing and https://learn.chatgpt.com/docs/agent-approvals-security (sandbox, `approval_policy`, protected paths), https://learn.chatgpt.com/docs/config-file/config-reference (every `-c` key), https://learn.chatgpt.com/docs/config-file/environment-variables, https://learn.chatgpt.com/docs/codex-sdk (inline `-c permissions.<name>={…}` syntax), and the item/event types in https://github.com/openai/codex/blob/main/sdk/typescript/src/events.ts and `items.ts`. 0.166.0 is the minimum: an older Codex might ignore an override it doesn't know without saying so, and a dropped deny rule would fail open.
263. **The policy goes in a per-run permission profile, not `--sandbox`** (T30). Codex's older `--sandbox workspace-write` can't deny reads (`~/.ssh` stays readable), which the ticket says must be refused, so every role would be refused. Permission profiles (beta) can: `-c default_permissions="spoolhq" -c permissions.spoolhq={…}` with `extends=":workspace"` for the implementer (the documented successor of workspace-write) and, for the reviewer and planner, `":root"="deny", ":minimal"="read", ":workspace_roots"={"."="read"}` (read-only, reads confined to the worktree, like Claude Code's Read); every denied path `"deny"`, `network={enabled=false}`. `--sandbox` is never passed, since "If `sandbox_mode` appears in any loaded config file, you pass `--sandbox`, … Codex uses those older sandbox settings instead of `default_permissions`" (permissions doc). The deny list adds `~/.codex` and `CODEX_HOME` (Codex's `auth.json`).
264. **How Codex enforces each part** (T30). Writes confined: the `:workspace` profile in bubblewrap+seccomp (Linux) or Seatbelt (macOS), worktree `.git`/`.codex`/`.agents` read-only. Read-only: no `write` entry. Approvals never asked: `approval_policy="never"` (so nothing escalates outside the sandbox). Network off: profile network disabled, `web_search="disabled"`, `features.apps=false`, `features.plugins=false`, `features.multi_agent=false`; MCP servers come only from config files SpoolHQ doesn't load. Denied reads: profile `deny` entries. The stream check stops a run on an `mcp_tool_call` or `web_search` item, or a file change by a read-only run (`policy not enforced: …`); Codex has no `init` listing tools, so there's no up-front check.
265. **No per-command allowlist in Codex; its sandbox stands in for the implementer** (T30). Codex's `.rules` only decide what may run *outside* the sandbox, and with `approval_policy="never"` nothing does. Accepted as equivalent: for Claude Code the allowlist isn't the boundary either (an allowed `just test` runs tests the agent wrote, DECISIONS 90); the OS sandbox is, and Codex's confines writes to the worktree and temp folders, has no network and denies the credential files; the gates still run install, lint and test outside the agent before anything merges. So the part "the shell allowlist" counts as enforced exactly when the sandbox and denied reads are. The difference is recorded in `docs/agents.md`: a Codex implementer can run any command inside that sandbox, and a Codex reviewer or planner can run read-only commands (Claude Code's has no shell).
266. **Refuse, per role, what Codex can't enforce here** (T30). `detect()` reports `policy_parts` (role → part → enforced; new optional `BackendInfo` field) and `run()` refuses before starting with `backend 'codex-cli' can't enforce <part>; choose another backend for the <role> role`, naming the first missing part. `AgentPolicy` gained `role` (`implementer`; `read_only_for(…, role="reviewer")`, the planner passes `planner`) so the message can name it. Not enforced: Linux without `bwrap` on PATH (Codex would fall back to a bundled helper or warn), a `/etc/codex/config.toml` that sets `sandbox_mode`/`[sandbox_workspace_write]` or can't be parsed (profiles would be ignored), other OSes; native Windows is refused for denied reads (the deny rules depend on MXC or the elevated sandbox, which SpoolHQ can't check; use WSL2), like Claude Code's native-Windows refusal.
267. **Per-run settings without a per-run `CODEX_HOME`** (T30). `--ignore-user-config` is the documented way to keep the login while dropping the user's settings ("Do not load `$CODEX_HOME/config.toml`. Authentication still uses `CODEX_HOME`."), so all settings are `-c` overrides; a temp `CODEX_HOME` would lose the ChatGPT login. A repository's `.codex/` layers load only for trusted projects and trust lives in the user config, so they are skipped; `--ignore-rules` and `features.hooks=false` cover rules and hooks; `--ephemeral` and `history.persistence="none"` keep sessions off disk. SpoolHQ never writes `~/.codex`; Codex itself may refresh its login there.
268. **Codex's environment** (T30): the shared allowlist plus `CODEX_HOME` and `CODEX_CA_CERTIFICATE` (documented as read by Codex) and `npm_config_verify_deps_before_run=false`; `OPENAI_API_KEY` and `CODEX_API_KEY` never pass (an API-key login is `codex login --with-api-key`). `shell_environment_policy.ignore_default_excludes=false` strips variables named like KEY/SECRET/TOKEN from the agent's commands, including the endpoint token.
269. **Codex's custom endpoint** (T30): a per-run provider, `-c model_provider="spoolhq" -c model_providers.spoolhq={name=…, base_url=…, env_key="SPOOLHQ_ENDPOINT_TOKEN_CODEX_CLI"}`, with the step 0 token (261) in that variable; `requires_openai_auth` defaults to false, so the ChatGPT login is not sent there. `model` becomes `--model`. Codex speaks only the Responses API (`wire_api` "`responses` is the only supported value").
270. **Codex usage, limits and denials** (T30). `turn.completed.usage`: `input_tokens` (includes the cached part, as SpoolHQ stores it), `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`. Cache weight a tenth, the existing `weighted_tokens`: https://learn.chatgpt.com/docs/pricing lists cached input at 25/250 credits for GPT-6 Astra and 5/50 for GPT-6 Sol (a tenth) and 2.5/50 for GPT-6.1 Sol (a twentieth); a tenth is the more conservative documented weight, confirmed rather than assumed. A `turn.failed`/`error` message containing "usage limit" is `usage_limited` with `reset_at=None`: Codex documents neither the message nor a reset time (the fixture's wording is illustrative). Denials are a failed `command_execution` whose output says `Operation not permitted`, `Permission denied`, `Read-only file system` or `sandbox` (best effort; Codex has no denial event). `max_turns` and `max_usd` have no Codex option and aren't enforced; `max_tokens` is checked when a turn reports usage. The Codex transcripts in `tests/fixtures/agents/codex/` are hand-built from the documented format, since Codex isn't installed here.
271. **One process session for both CLIs** (T30). `claude_cli._Session` moved to `services/agents/process.py` as `Session` with a small `StreamParser` protocol, so the Codex adapter reuses the pipes, stop sequence and teardown; `claude_cli.py` stays under 500 lines.
272. **Terms check: unclear** (T30, 2026-10-30). OpenAI's Terms of Use (https://openai.com/policies/row-terms-of-use/) say users may not "Automatically or programmatically extract data or Output" and "You may not share your account credentials or make your account available to anyone else". The Codex docs themselves document running `codex exec` from scripts with a ChatGPT login ("Use this path only if you specifically need to run as your Codex account", https://learn.chatgpt.com/docs/non-interactive-mode, "Use ChatGPT-managed auth in CI/CD (advanced)"), and a Codex maintainer wrote that "our terms of use and code license are quite permissive, and OSS projects like OpenCode are doing things similar" (https://github.com/openai/codex/discussions/8338, 2025-12-19, "I'm an engineer, not a lawyer"). No statement explicitly covers a third-party tool driving the official `codex` binary with a subscription login. Not blocking.
273. **Warn, don't refuse, for a Codex reviewer or planner** (real Codex check, 2026-10-31). A read-only Codex agent can run read-only shell commands where Claude Code's has no shell (265). `READ_ONLY_SHELL` in `services/agents/backends.py` names such backends; `Agents.shell_warnings()` turns the project's planner and reviewer into warning lines, printed by `spool agents --project` (stderr) and logged at run start; plain `spool agents` adds a `warning` line under `codex-cli`. Behaviour is unchanged. Steps 1–6 of the chore (real Codex runs, sandbox denials, limits, fixtures) were not done: Codex was not installed on the machine.
274. **Real Codex 0.166.0 findings** (real Codex check, 2026-10-31, Fedora, ChatGPT login). (a) The standalone installer puts Codex in `~/.codex/packages/standalone/releases/<version>/` and Codex re-runs that binary inside bubblewrap, so denying all of `~/.codex` stopped every run (`bwrap: execvp …/bin/codex: Permission denied`); a more specific `"<release>"="read"` did not override the deny. Now, when the resolved `codex` is inside a denied Codex folder, that folder's entries are denied one by one except the path down to the release (`denials_except`, shared with the SpoolHQ-home rule; symlinks skipped because bwrap can't mount over them: `Can't mount on symlink destination …/standalone/current`), and read-only profiles get `"<release>"="read"` (without it every reviewer/planner command failed with `execvp … No such file`). `auth.json` was then checked unreadable from both profiles. (b) `--strict-config`: 0.166.0 silently ignored `tools.view_image` (an `error` item: "`tools.view_image` is ignored"); with the flag an unknown `-c` key or feature name stops Codex before it starts, closing the fail-open gap 262 worried about. (c) `codex features list` showed browser use, CDP access, computer use, in-app browser, remote plugins, skill MCP dependency installs, tool suggestions and `view_image` on by default; all are now off. `code_mode_host` must stay on (off, tools fail closed). (d) Denials: commands the sandbox stops on the filesystem don't appear in `--json` at all (tried with `unified_exec` off too: no change), so only network denials (`Could not resolve host`, now matched) are logged; enforcement was confirmed from the agent's own report and the file system. `files_changed` is best effort for Codex; the real test now checks the file on disk. (e) `:workspace`'s temp folders include all of `/tmp`: a write to a scratch folder under `/tmp` outside the worktree succeeded (the reviewer flagged it, `needs_human`); a write to the home folder got `Read-only file system`. Documented, not changed. (f) The token budget only applies after Codex's single turn (usage arrives in `turn.completed`); the ticket is then blocked. Timeout and cancel stop it mid-run.
275. **Refuse Codex in a worktree under a shared temp folder** (Codex worktree guard, 2026-10-31). Codex's `:workspace` profile lets the agent write anywhere in the temp folders (274e), so a worktree there could reach other tickets' worktrees or any temp file. Before starting, `CodexCliRunner.run()` resolves the worktree (symlinks followed) and refuses it with `backend 'codex-cli' can't run in a worktree under <dir>: its sandbox can write anywhere there; set worktrees_dir outside temp folders` when it is inside `/tmp`, `/var/tmp`, `$TMPDIR` (from the environment Codex gets) or `tempfile.gettempdir()`; each folder is resolved too, so macOS's `/tmp` → `/private/tmp` counts. `<dir>` is the folder as listed, not resolved. The check runs in `run()`, not `detect()`, since only `run()` knows the worktree; `spool agents` applies it to `worktrees_dir` as a `worktrees` line instead of changing `policy enforceable`. Tests opt out with the `allow_temp_worktree` constructor argument, which `make_runner` never passes, so `project.yaml` and the environment can't switch it on. Known limits written down in `docs/agents.md` ("Codex: known limits"): unreported filesystem denials, the token budget acting only after the turn, and the npm install still unchecked.

278. **SpoolHQ gives the SDK its own `Transport`** (T31). 280. **The policy per role, twice: Claude Code's options and a `PreToolUse` hook** (T31). 291. **A line the Agent SDK can't parse is skipped, not fatal** (T28 follow-up; resolves the open point in 285). In claude-agent-sdk 0.2.176, `query()` calls `parse_message` on each non-control line. A `MessageParseError` (for example `Missing required field in assistant message: 'model'`) ends the message iterator, and the SDK can't be told to skip a line. SpoolHQ owns the `Transport`, though. `CliTransport` now runs the same `parse_message` (imported from the SDK's private `_internal.message_parser` and `_errors`, as the version is pinned) on each line in stdout order, after the tap. A rejected line still reaches SpoolHQ's stream parser, so the policy checks still see it, and the transcript. It is withheld from the SDK and reported as a `StreamWarning` event (text and line cut to 500 characters) plus a log warning, and reading goes on to the result. If the rejected line is the result itself, the transport closes stdin, which the SDK would otherwise do on seeing the result; without that, a real CLI would wait until the timeout. Without any result, the error is `Claude Code output could not be parsed: <error> (line N)`, where N counts stdout lines including the control protocol. No sleep or retry: every decision is made on the reading task, in order. Measured: 0 failures in 200 runs, 8 in parallel. The Codex adapter needs nothing: it parses its own JSON lines in one synchronous loop (bad JSON is `invalid_lines`, malformed events `unknown_events`).
