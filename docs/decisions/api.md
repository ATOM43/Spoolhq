# Decisions · API

REST routes, WebSocket, errors, the CLI and TypeScript clients, secrets. Listed in [DECISIONS.md](../../DECISIONS.md).

23. **The CLI's HTTP client ignores proxy environment variables (`trust_env=False`).** The daemon is always local; a user's `HTTP_PROXY` must not route CLI calls through a proxy.
175. **The run endpoints live in `api/routers/runs.py`** (models in `api/schemas/runs.py`), following the codebase's one-router-per-resource layout rather than the ticket's `api/runs.py`. Unknown project, run or ticket → 404; any other refusal → 409; the message is in `detail`, which the CLI's client now prints for 404/409 answers (`ApiClient.post` added).
295. **Route inventory and renames** (T19 step 0). Existing before T19: `GET /api/health`, `GET /api/version`, `POST …/runs` (`{"mode", "ticket"}`), `POST …/runs/{id}/pause|resume|cancel`, `GET …/runs/current`, `POST …/tickets/{id}/approve|integrate|reject|discard`, `POST …/plan`, `POST …/plan/approve`, `POST …/github/sync`. The CLI used start, pause/resume/cancel, current, approve/reject/discard, github sync and version (`spool plan` calls the planner directly). Renamed to the ticket's scheme: start is `POST …/run/next`, `…/run/all`, `…/run/ticket/{id}`, control is `POST …/run/pause|resume|cancel` on the project's current run (optional `?run_id=`, so `spool run pause --run` keeps working), plan generation is `POST …/plan/generate`. `spool run` changed in the same commit; the old routes are gone, not aliased. Kept: approve/integrate/reject/discard, `runs/current`, github sync.
296. **One error format, with stable codes** (T19). `api/errors.py` turns every non-2xx answer, including FastAPI's 404/405/422 and the middleware's 400/401/413, into `{"error": {"code", "message", "field"}}`. `RunLoopError` gained a class attribute `code` (`conflict`, `not_found`, `run_locked`, `not_blocked`) instead of a new exception per route; `service_errors()` maps service exceptions in one place. A `ProjectError`/`TicketError` whose message starts with `no ` is a 404 (a shortcut comment says to give them a NotFound class if a message changes). Validation messages never echo the input (it can be a secret or untrusted ticket text). `spool`'s client reads `error.message`.
297. **ETags: a per-project in-process lock, not an OS file lock** (T19). `write_if_match` compares and writes under a `threading.Lock` per workspace: the daemon is the only API writer, and `acquire_lock` is non-blocking, so concurrent API edits would fail instead of serialising. The window against `spool tickets edit` and external editors (they don't take the lock) is documented in `api.md`. A ticket PUT is `edit_ticket` in the scheduler (load, check the transition when the status changes, assign `meta` and `body`, `save_ticket`), so the store's changed-keys-only rewrite gives byte-identical round-trips (tested on every T05 fixture). Settings go through `parse_project` + `save_project`, so an unchanged PUT writes the same bytes too.
298. **Unblock continues the blocked run** (T19). `POST …/tickets/{id}/unblock` with a note reopens the ticket's latest run (`reopen_run` now accepts `blocked` as well as `interrupted`), moves the ticket `blocked → running` (in the transition table already) and starts a `pr_changes` attempt in the kept worktree, reusing reject's note path, so the prompt's "Note from the user" has it. No new attempt kind. A ticket that isn't blocked, or whose latest run isn't, is 409 `not_blocked`; a worktree that is gone blocks again with the discard hint, as resume does.
299. **Paging by `(started_at, id)`** (T19). `services/runs/history.py` orders runs `started_at DESC, id DESC` and pages with `WHERE started_at < ? OR (started_at = ? AND id < ?)`; the cursor is unpadded URL-safe base64 of `started_at|id`. A new run sorts before any cursor, so it can't repeat on a later page. It reads through `RunLog._reading` (like `journal.py` uses the transaction) because `log.py` is at the 500-line limit. `limit` above 200 is 400 `limit_too_large` (not 422), as the ticket asks.
300. **The WebSocket checks the token itself** (T19). `LocalOnlyMiddleware` skips the bearer check only for a WebSocket on `/api/projects/{name}/events` (a regex, so a future WebSocket is still protected by default); the Host check still applies. The token is compared with `hmac.compare_digest` after a 5 s `wait_for`. Origins come from a new setting, `allowed_origins` (default: `tauri://localhost`, `http://tauri.localhost`, `https://tauri.localhost`, `http://localhost:1420`); a refused origin is closed before accept (403). An unknown project is accepted, authenticated, then closed 4404, so its existence isn't told to unauthenticated clients.
301. **How events reach a socket, and the threading rule** (T19). Events are appended, and so published, on the run loop's worker thread, the plan job's thread, the GitHub poller's thread or a FastAPI thread-pool thread (every route is a sync `def`); never on the event loop. The bus calls `notify(subscription)` on that thread while holding its lock; the listener drains the subscription with `get(timeout=0)` (its own short condition lock, never the bus's or the run log's) and does only `loop.call_soon_threadsafe(put, event)`. `put` runs on the event loop and does `queue.put_nowait`; on `QueueFull` it sets `too_slow`, and the handler closes 4408. `call_soon_threadsafe` is correct from the loop thread too, so the rule holds wherever an event comes from. Envelopes look up the run's ticket and the attempt's number (cached per connection) with `asyncio.to_thread`. Replay reads SQLite in batches of 500, after subscribing; duplicates are dropped by `seq`. Heartbeat is an application message, `{"type": "ping"}`, after 20 s idle, so a browser client can see it.
302. **Closing with 1001 on shutdown** (T19). uvicorn closes open WebSockets itself with 1012 before the app's lifespan shutdown runs. `spool serve` now runs a `uvicorn.Server` subclass whose `handle_exit` first asks every stream to close with 1001 (each on its own loop, `call_soon_threadsafe`); lifespan shutdown does the same for servers that get there with sockets open. `EventStreams` (`app.state.streams`) holds the streams' stop functions.
303. **The TypeScript client goes through Rust, and the WebSocket token comes from the caller** (T19). The T03 decision keeps the token out of the webview, and the CSP only allows `ipc:`, so `openapi-fetch` gets a custom `fetch` that calls a new Rust command `daemon_request` (GET/POST/PUT/DELETE only, `/api/...` paths with a percent-encoded query, JSON body, `If-Match`, and the `ETag` back); `daemon_get` shares its code. Errors map exactly as T03's (`replyError`, shared), plus a new `api` kind with `code`, `message`, `field`, `etag`, `current`. The WebSocket helper can't go through Rust, so it takes `getToken()` and needs `connect-src ws://127.0.0.1:*` in the CSP; both are T20's wiring (no command exposes the token yet), recorded here so T20 doesn't miss them.
304. **The generated files** (T19). `openapi-typescript` **7.13.0** (dev) and `openapi-fetch` **0.17.0**, the latest on npm on 2026-11-01, pinned exactly. `openapi-typescript` declares a peer of TypeScript 5; it ran cleanly on our 6.0.3. `scripts/dump_openapi.py` builds the app with `Settings.model_construct()` (no config file or environment) and no lifespan, so the schema doesn't depend on the machine. `openapi.json` and `schema.gen.ts` are excluded from Prettier and ESLint, and `schema.gen.ts` from the 500-line limit (`ALLOWED`). The event envelope and data models are added to `components.schemas` by a custom `openapi()`; `data` stays a free-form object in the envelope, the per-type models (`RunStatusData`, …) allow extra keys. No Python dependency was added.
305. **Secrets** (T19). `services/secrets/` (new package) lists `anthropic`, `github` and `clickup` with their environment variables and keychain keys, reusing the agents' and GitHub's constants; ClickUp had no secret code yet, so it is `SPOOLHQ_CLICKUP_TOKEN` / key `clickup`, ready for the tracker. A keychain error is reported by exception type only, since its text could quote what was stored. Deleting a secret that isn't there is a 204.
311. **Trying a stack command is project-scoped, after creation** (T20). `POST /api/projects/{name}/commands/test` runs in the project's registered `repo` rather than at a path the request names, so the endpoint can't be pointed at an arbitrary folder. That makes the New project dialog two steps: create (name, repo or template), then the three commands from `project.yaml`, each with **Test**, saved with `PUT …/settings` and the ETag from the load. A template's folder has nothing to test before generation anyway. `gates.try_command` reuses `_run_gate` (split without a shell, the scrubbed environment, the process-tree timeout) with a temp log that is removed afterwards, a 1 MB log cap, and an excerpt for passes too. The timeout is 90 s, below the desktop app's 120 s request timeout; runs keep the project's own. `GET /api/templates` lists the built-in templates only; folder and git URL templates stay CLI-only for now.
315. **The daemon says what can run** (T32). The run controls need the scheduler's answer ("Run next (T11)", "T09 is blocked"). Re-deriving it in TypeScript would duplicate `next_ready` and `explain_idle`, so `ProjectDetail` gained `next_ticket`, `idle` (`{code, ticket_ids, message}`, plus an `invalid_plan` code when `require_valid` fails) and `remaining_h`. `CurrentRun` gained `cost_micro_usd`, so usage shows USD for API-key backends and tokens otherwise. Usage is the latest run's, since no endpoint sums a project's usage yet. The header says "(latest run)".
322. **The daemon ships a WebSocket library** (T32, found in the real `just dev` run). `uvicorn` serves WebSockets only with `websockets` or `wsproto` installed, and neither was a dependency. Under `spool serve`, every event stream got an HTTP 401 ("No supported WebSocket library detected"), so the desktop app never saw a live event. Tests use Starlette's TestClient, which doesn't need one, and that is why this went unnoticed since T19. `websockets` **17.2** (2026-10-03) is now pinned exactly; 17.3 and 17.4 were under two weeks old. A new integration test starts `spool serve` and opens the socket (authenticated, then 4404 for an unknown project).
323. **An invalid `project.yaml` is reported, not raised** (T33). `GET /api/projects` and `GET /api/projects/{name}` load each project's settings themselves and, when they fail, return the project with `settings_error: {file, field, message}` (the first problem; `split_error` splits `project.yaml: <field>: <message>`, and a whole-file problem has no field) instead of a 422 for the whole list. The detail's `repo`, `default_branch` and `remote` are then null, the run isn't read and `run_state` is `idle`, so no project is ever "unknown". The UI shows **Settings invalid** in red with that line, on Home and as a bar under the panel header with the path (copy) and **Reload**; there is no **Open file** without an opener plugin.
