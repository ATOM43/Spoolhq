# Decisions · Desktop

Tauri, the React UI, CSP and frontend tooling. Listed in [DECISIONS.md](../../DECISIONS.md).

2. **UI: Tauri 2 + React + TypeScript.** Small native binaries on all three desktop platforms, with a mainstream, well-typed UI stack.
11. **TypeScript pinned to 6.0.3, not 7.x.** typescript-eslint 8.71 supports TypeScript < 6.1; revisit when typescript-eslint supports 7.
24. **The daemon token stays in Rust.** The web view calls only the Rust commands `daemon_info` (port and whether a token exists) and `daemon_get` (status and body); Rust reads `~/.spoolhq/token` on each request and adds the `Authorization` header. Script in the web view can never read or leak the token, and the daemon needs no CORS.
25. **No HTTP plugin; the scope lives in the command.** `daemon_get` only builds `GET http://127.0.0.1:<port>/api/...` URLs from a character-checked path, and its client ignores proxy variables. The window's one capability grants just the two app commands (no `core:default`), via permissions generated from `build.rs`.
26. **Strict CSP.** Scripts, styles, fonts and images from `'self'` only, `connect-src` limited to Tauri IPC, `object-src`/`base-uri`/`form-action`/`frame-ancestors` `'none'`, plus `freezePrototype`. Tauri injects it into the built app; the Vite dev server in `pnpm tauri dev` is not covered.
27. **Settings uses the native `<dialog>`, not Radix Dialog.** Radix's scroll lock injects a `<style>` element, which `style-src 'self'` blocks; `<dialog>` traps focus and closes on Escape on its own.
28. **Fonts are bundled with `@fontsource`, no CDN.** Inter (400/500/600) and JetBrains Mono (400) ship as files (`assetsInlineLimit: 0`), so the app works offline, makes no third-party requests, and the CSP can stay `font-src 'self'`.
29. **shadcn/ui components use SpoolHQ's token names** (`bg-surface`, `text-ink-muted`, `bg-accent`, …) instead of shadcn's (`primary`, `muted`, `accent`), because shadcn's `accent` is a hover grey that clashes with our accent blue. They were copied from the new-york-v4 source and restyled.
30. **Status rules.** Health (no token) is checked before version, so a stopped daemon reads as "not running" even without a token file. A daemon that was reachable shows "Reconnecting…" for up to three failed checks (about 9 s), then "Daemon not running"; one that never answered is "not running" at once. Token, 401, 400 and other failures show a fourth state, "Daemon error", with the reason on Home.
31. **The app reads the port like the daemon:** `SPOOLHQ_PORT`, then `port` in `config.toml`, then 8765. Port and token are re-read on every check, so starting the daemon after the app needs no restart.
32. **Rust is pinned like the rest:** toolchain 1.99.1 in `rust-toolchain.toml`, crates with `=` versions, and `--locked` in the justfile. CI installs the toolchain with the runner's own rustup rather than a third-party action, and does not cache Rust builds yet.
33. **`@tanstack/react-query` is pinned to 5.104.3, not 5.104.4.** pnpm 12's minimum release age rejected the day-old 5.104.4; we pin an older release instead of exempting packages from the policy.
35. **Frontend: Feature-Sliced Design, enforced by lint.** `desktop/src/` is split into app, pages, widgets, features, entities and shared; slices expose an `index.ts`, import only from lower layers and never from a sibling slice. `eslint-plugin-boundaries` 7 checks this in `just lint`. We chose it over Steiger (the FSD project's own linter) because it runs inside ESLint, which we already run, and does not flag our deliberately empty placeholder slices.
37. **Design tokens live in `shared/styles/tokens.css`;** `app/styles/global.css` imports them with Tailwind, the fonts and the base layer.
38. **`unrs-resolver`'s install script is not run** (`allowBuilds` in `desktop/pnpm-workspace.yaml`). `eslint-import-resolver-typescript`, which lets the boundaries rules resolve `@/` imports, gets its native binary from an optional prebuilt package; the script is only a fallback.
306. **Plan: T20 split into T20 and T32** (T20 step 0, 2026-11-01). T20 is now "Event bridge, Home and New project" (2 h); "Settings, project panel and Spec tab" is the new T32 (Phase 4, depends on T20, 2 h), and T21 and T22 depend on T32. 31 tickets, 77 h. The critical path is T01 → T02 → T04 → T05 → T06 → T13 → T19 → T20 → T32 → T22 → T23 → T26, 28.5 h. Two other paths tie at 28.5 h (through T11 → T12 instead of T05 → T06, and through T25 instead of T23); the plan keeps the path it already listed.
307. **Events go through Rust, so the CSP is unchanged** (T20; replaces the plan in 303). `events.rs` holds the WebSocket: `events_subscribe(project, since, channel)` re-reads the port and token on every connect (like the HTTP commands), sends the auth message first, forwards each envelope with a `seq` above the last over a Tauri `Channel`, and reconnects with `since=<last seq>` after a drop or any non-final close (0.5 s doubling to 10 s, reset after a connection). 4401, 4404, 1008 and a refused handshake (403) are final and reach the webview as `{"kind": "stopped", "reason"}`. A missing token or daemon is retried, since the daemon may simply not be up yet. Each stream owns a `watch` receiver; `events_unsubscribe` and window `Destroyed` drop the sender, and the stream closes with 1000. The project name is checked against the route pattern before it goes into the URL. Rust sends no `Origin`, which the daemon allows (the token still applies). Tauri channels deliver over IPC, and `plugin:__TAURI_CHANNEL__|fetch` is exempt from the ACL (tauri 2.12.4, `webview/mod.rs`), so neither the CSP nor the capability needed a change for them. `getToken()` is gone.
308. **The Rust WebSocket crate** (T20). `tokio-tungstenite` **=0.30.0** (2026-07-11, the latest), with default features off and only `connect`: plain `ws://` to 127.0.0.1, no TLS stack. It needs `tokio` (`macros`, `sync`, `time`; `net` and `rt` for tests), `futures-util` (`sink`) and `serde_json` as direct dependencies; all were already in the lock file through Tauri and are pinned to the locked versions (=1.53.3, =0.3.34, =1.0.154), so the only new crates are tokio-tungstenite and tungstenite.
309. **The folder picker is Tauri's dialog plugin** (T20). The ticket asks for the Tauri folder picker, which is a plugin in Tauri 2: `tauri-plugin-dialog` **=2.8.3** and `@tauri-apps/plugin-dialog` **2.8.3**, exact. 2.8.4 (2026-10-28) was under two weeks old. The capability grants only `dialog:allow-open`. `pickFolder()` lives in `shared/api` so tests mock it at that boundary.
310. **Run events invalidate queries, coalesced** (T20). Envelopes don't carry done/total, so patching would mean re-deriving the daemon's counts; the hook invalidates instead. `run.*`, `integrate` and `policy.decision` invalidate `["projects"]` (list and detail) and the project's tickets; those plus `attempt.*`, `gate.result` and `review.verdict` invalidate its `["runs", name]`. `agent.*` and `log` change nothing on Home, so a busy agent causes no refetches. Invalidations wait 250 ms and go out once, so a burst (a replay, a run finishing) is one refetch. Query keys live in `shared/api/keys.ts`, so the project slice can invalidate run and ticket data without a sideways import. The last `seq` per project is kept in memory, so returning to Home resumes. The shortcut this entry recorded (a first subscription replayed the whole history from `since=0`) is resolved in T32 (313): the stream starts after the REST answer's `latest_seq`.
312. **Home's states** (T20). The project list is mounted only while the daemon status is ok; when the daemon comes back the section remounts and its stale query refetches, so Home recovers with no reload. A project's status is one icon + label, most urgent first: Running, Paused, Needs you, Unknown, No plan yet, Done, Idle. "Needs you" fetches tickets only for projects whose `needs_you` is above 0 and lists Blocked, Awaiting approval and Paused runs once each. The new dialog uses the native `<dialog>` (as the T03 Settings dialog does) and the progress line a native `<progress>`, so neither needs inline styles or a new UI library. `screens-prompt-v0.md` is not in the repository; the screens follow the ticket and the existing tokens in `shared/styles/tokens.css`.
313. **Subscribing from the latest event** (T32 step 0; resolves the shortcut in 310). The app started a project's first stream at `since=0`. Now `ProjectSummary` (so the list and the detail) and `CurrentRun` carry `latest_seq`, the run log's `MAX(id)`, read *before* the rest of the answer. A state read after an event is then never older than the stream's start, and an event written between the REST call and the subscribe is replayed, since replay covers everything after `since`. `useProjectEvents(projects)` takes `{name, latest_seq}` and starts at the larger of that and the last `seq` it saw; the value is read through a ref, so a refetch doesn't restart the stream. A run log that won't open gives `latest_seq` 0, as before. Full history is read only with `GET …/runs/{id}`.
316. **Panel state and the tab it opens on** (T32). `pages/project/model/state.ts` maps the project, current run and spec to one section-8 row. An active run is running, paused (by the user), or paused with `reset_at` (usage limit, "resumes HH:MM", Cancel only). A running `plan` run means "Planner is running". `next_ticket` means Run next / Run all. Otherwise the disabled reason comes from `idle.code`, or "Write a spec first" / "Generate a plan first" when there are no tickets. The tab is chosen once, when the data first arrives, so starting a plan doesn't pull the user off the Spec tab. The Spec tab stays mounted (`forceMount`, hidden), so switching tabs never drops an edit that isn't saved yet.
317. **Disabled controls carry their reason** (T32). `shared/ui` `ReasonButton` disables itself when `reason` is set. The reason is a `title` tooltip on a wrapper (a disabled button gets no pointer events) and the button's accessible description, which is what the tests assert. Native `title` is used rather than a Radix tooltip, whose positioning sets inline styles (CSP `style-src 'self'`).
318. **Spec autosave** (T32). `useSpecAutosave` keeps the text and the last saved `{content, etag}`. One timer runs 1 s after the last change, only while nothing is saving, no conflict is open and the last save didn't fail; Ctrl/Cmd+S saves at once. A 412 opens the conflict bar with the disk version from the error's `current`, and stops saving. **Reload** takes the disk version, and **Keep mine** saves with the disk ETag, only on that click. A failed save shows Error and retries on the next edit or Ctrl+S, not in a loop. Each save writes the new `{content, etag}` into the spec query, so a remount starts from disk, not from the first load. Generate plan is disabled while the spec isn't saved, since the planner reads the file.
319. **Generate plan, Re-plan and failures** (T32). The button is disabled for an empty spec ("Write at least an objective first") and while a draft plan waits for approval (`idle.code == plan_not_approved`), as the ticket asks. With tickets it is **Re-plan**, behind the D4 confirm, which states the planner's rule (unedited drafts are replaced, edited and approved tickets kept); the daemon has no "keep edited" option to ask about. Progress is the plan run's state and its last phase line, refreshed by run events. A plan run ending `blocked`, or a failed `POST`, shows the red bar with the reason and **Retry**. "View log" waits for the Run tab (T22).
320. **Markdown renderer** (T32). `react-markdown` **10.1.0** (2025-03-07, the latest), exact. It builds React elements from an mdast/hast tree, never HTML strings. `skipHtml` drops raw HTML, and `defaultUrlTransform` empties any URL that isn't http(s), mailto, tel or relative (so `javascript:` is gone). Links get `onClick` `preventDefault`, so a spec link can't navigate the webview away from the app (the app has no opener plugin; opening links is left for later). No GFM plugin: tables and task lists render as text. ESLint `no-restricted-syntax` bans `dangerouslySetInnerHTML`, both as a JSX attribute and as an object key.
321. **Settings** (T32). `features/open-settings` became `features/settings` and `pages/project-panel` became `pages/project`, as the ticket names them. "Ready" means an installed, logged-in backend or a saved Anthropic key. The dialog opens by itself only on Home (`firstRun`), and is not closable (Escape is cancelled, Close is disabled with the reason) only while the agents and settings have loaded and nothing is ready. If either fails to load, it can be closed, so a daemon problem is never a trap. A secret is saved by a plain `api.PUT`, not a TanStack mutation, so the value never sits in the mutation cache. The field is cleared before the request resolves, and the status refetches. A secret from an environment variable can't be removed here; Remove says so. General shows the daemon's folders read-only (they come from `config.toml` / `SPOOLHQ_*`). Theme, OS notifications and "keep running when closed" have nowhere to be stored yet and are left out. About shows the version, the daemon's address and the repository URL as copyable text, and has no logs **Open** button: the daemon doesn't expose its logs folder.

375. **The Run tab's Gates, Review and Diff panels** (T39). `entities/run` `useArtifact(name, project, run, attempt, stamp)` loads one report; 404 `not_ready` is data (null), not an error. `stamp` is the `seq` of the event after which the report changed — the gates or review step ending, the commit's `run.phase` for the diff — so a new stamp is a new query key and the report refetches once, with no polling; the old report stays on screen meanwhile (`keepPreviousData`). The panels show the attempt in view (`useRunEvents`' attempt live, or a finished `?attempt=N` under its outcome), so switching attempts reloads them. A failed or timed-out gate starts open, others open on click; its output is lines of plain text, the first failure line highlighted, labelled for screen readers and scrolled to inside the output box only. The patch is parsed by `shared/lib` `parsePatch` (hunk headers, numbers across hunks, `\ No newline` notes, CRLF), about 40 lines, no dependency. Agent edit events carry only counts, so a transcript file-edit row's mini diff is that path's patch from the attempt's diff (the attempt's net change to the file, not the single edit), its first 50 lines with **Open in Diff**; before the commit it says the lines come then. Reasons and the summary go through the safe `Markdown`; gate output, item text and diff lines are text nodes. `useRunLimits` moved the `limits` read from `run-view` to `entities/run` so the note dialog can use it too. The drawer's gate and review lines (`AttemptChecks`) read the same reports for the latest attempt: in "Why it needs you" and under the newest finished row of Attempts.
376. **Where the spec won over the V2 PNGs** (T39). The Run tab PNG's gate rows show a live test log and a "Attempt 1 · just lint failed" card under them; the daemon has no streaming gate output, so a running gate is "Running just test…" and an earlier attempt is opened from the drawer's Attempts (`?attempt=N`), not stacked under the current one. Gate rows carry an explicit state label beside the icon and the gate's name, since status is never icon or colour alone. The drawer PNG's "Gates: just lint · just test (142 passed)" becomes the prompt's "Gates: 2 of 3 passed · test failed": test counts aren't in the report, and skipped (unset) gates don't count. The Diff tab shows its file count once the diff exists ("Diff 6 files"), which T22 left out. The note dialog's "Starts attempt 3 of 6 · 1 review retry left" sits in its footer; with **Reset retry count** on, it shows the full review retries.
378. **Past runs and replay** (T40). `widgets/run-history` is the table (`entities/run` `useRunHistory`, an infinite query under the project's runs key, so the run events that already invalidate that key refetch the loaded pages and a finished run appears on top; no polling, no events read). A row (and its **Replay** button, the keyboard way in) opens the run's last attempt; the chip opens the drawer. A replay lives in the URL as `?run=7&attempt=2`: attempt numbers count per ticket, so the run id is what makes the link complete without opening the drawer (`?ticket=`), and the drawer's attempt links now set both. `?run=` alone opens the run's last attempt. `widgets/run-view` `RunLayout` is the header, transcript and details that `RunView` (live) and `Replay` share, so the two can't drift; `Replay` adds the grey banner and passes no result panel, so no run control renders (Unblock and Review are in the drawer). The banner says "Viewing attempt 2 of 4", where 4 is the run's last attempt number; an earlier attempt shows its own verdict ("Gates failed"), the last one the run's outcome ("Blocked"). The arrows move inside the run. Replay uses `useRunEvents` with `live: false`: pages of 2,000 through the events route with a `<progress>` bar from `total`, never `subscribeEvents`. A step the attempt left running shows as skipped, and the reports load once (no event stamps). Events are cached per attempt with `gcTime: Infinity` and removed by `useDropRunEvents` when the project panel unmounts or its project changes. The page checks the replay before the watched run, so a run that starts meanwhile only adds **Show current run**; a replay of the attempt that is still running calls it at once. The live view of an ended run gets a **Past runs** button, since the table was otherwise unreachable until a reload.
379. **Where the spec won over the V2 · Run tab, idle PNG** (T40). One row per run with an **Attempts** count, not one row per attempt as in the PNG: the prompt's columns say so, and the attempts are one click away in the replay's arrows. Outcomes are the run statuses (Merged, Blocked, Needs approval, Cancelled, Interrupted, Paused) as icon + label, without the PNG's "approved by you" / "retried" suffixes, which no field records. No "21 runs · $12.80 total" beside the heading: the list is paged and has no count. **Load more** instead of "13 earlier runs · Show all". Usage as tokens or USD by backend, Finished as a relative time with the absolute one on hover; SpoolHQ, the dark theme from the tokens. The Last run summary keeps T22's one line rather than the PNG's green card with the tag and approver.
