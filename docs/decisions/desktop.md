# Decisions · Desktop

Tauri, the React UI, CSP and frontend tooling. Listed in [DECISIONS.md](../../DECISIONS.md).

2. **UI: Tauri 2 + React + TypeScript.** Small native binaries on all three desktop platforms, with a mainstream, well-typed UI stack.
11. **TypeScript pinned to 6.0.3, not 7.x.** typescript-eslint 8.71 supports TypeScript < 6.1; revisit when typescript-eslint supports 7.
24. **The daemon token stays in Rust.** The web view calls only the Rust commands `daemon_info` (port and whether a token exists) and `daemon_get` (status and body); Rust reads `~/.spoolhq/token` on each request and adds the `Authorization` header. Script in the web view can never read or leak the token, and the daemon needs no CORS.
25. **No HTTP plugin; the scope lives in the command.** `daemon_get` only builds `GET http://127.0.0.1:<port>/api/...` URLs from a character-checked path, and its client ignores proxy variables. The window's one capability grants just the two app commands (no `core:default`), via permissions generated from `build.rs`.
26. **Strict CSP.** Scripts, styles, fonts and images from `'self'` only, `connect-src` limited to Tauri IPC, `object-src`/`base-uri`/`form-action`/`frame-ancestors` `'none'`, plus `freezePrototype`. Tauri injects it into the built app; the Vite dev server in `pnpm tauri dev` is not covered.
27. **Settings uses the native `<dialog>`, not Radix Dialog.** Radix's scroll lock injects a `<style>` element, which `style-src 'self'` blocks; `<dialog>` traps focus and closes on Escape on its own.
28. **Fonts are bundled with `@fontsource`, no CDN.** Inter (400/500/600) and JetBrains Mono (400) ship as files (`assetsInlineLimit: 0`), so the app works offline, makes no third-party requests, and the CSP can stay `font-src 'self'`.
29. **shadcn/ui components use SpoolHQ's token names** (`bg-surface`, `text-ink-muted`, `bg-accent`, …) instead of shadcn's (`primary`, `muted`, `accent`), because shadcn's `accent` is a hover grey that clashes with our accent blue. They were copied from the new-york-v4 source and restyled.
30. **Status rules.** Health (no token) is checked before version, so a stopped daemon reads as "not running" even without a token file. A daemon that was reachable shows "Reconnecting…" for up to three failed checks (about 9 s), then "Daemon not running"; one that never answered is "not running" at once. Token, 401, 400 and other failures show a fourth state, "Daemon error", with the reason on Home.
31. **The app reads the port like the daemon:** `SPOOLHQ_PORT`, then `port` in `config.toml`, then 8765. Port and token are re-read on every check, so starting the daemon after the app needs no restart.
32. **Rust is pinned like the rest:** toolchain 1.99.1 in `rust-toolchain.toml`, crates with `=` versions, and `--locked` in the justfile. CI installs the toolchain with the runner's own rustup rather than a third-party action, and does not cache Rust builds yet.
33. **`@tanstack/react-query` is pinned to 5.104.3, not 5.104.4.** pnpm 12's minimum release age rejected the day-old 5.104.4; we pin an older release instead of exempting packages from the policy.
35. **Frontend: Feature-Sliced Design, enforced by lint.** `desktop/src/` is split into app, pages, widgets, features, entities and shared; slices expose an `index.ts`, import only from lower layers and never from a sibling slice. `eslint-plugin-boundaries` 7 checks this in `just lint`. We chose it over Steiger (the FSD project's own linter) because it runs inside ESLint, which we already run, and does not flag our deliberately empty placeholder slices.
37. **Design tokens live in `shared/styles/tokens.css`;** `app/styles/global.css` imports them with Tailwind, the fonts and the base layer.
38. **`unrs-resolver`'s install script is not run** (`allowBuilds` in `desktop/pnpm-workspace.yaml`). `eslint-import-resolver-typescript`, which lets the boundaries rules resolve `@/` imports, gets its native binary from an optional prebuilt package; the script is only a fallback.
306. **Plan: T20 split into T20 and T32** (T20 step 0, 2026-11-01). T20 is now "Event bridge, Home and New project" (2 h); "Settings, project panel and Spec tab" is the new T32 (Phase 4, depends on T20, 2 h), and T21 and T22 depend on T32. 31 tickets, 77 h. The critical path is T01 → T02 → T04 → T05 → T06 → T13 → T19 → T20 → T32 → T22 → T23 → T26, 28.5 h. Two other paths tie at 28.5 h (through T11 → T12 instead of T05 → T06, and through T25 instead of T23); the plan keeps the path it already listed.
307. **Events go through Rust, so the CSP is unchanged** (T20; replaces the plan in 303). `events.rs` holds the WebSocket: `events_subscribe(project, since, channel)` re-reads the port and token on every connect (like the HTTP commands), sends the auth message first, forwards each envelope with a `seq` above the last over a Tauri `Channel`, and reconnects with `since=<last seq>` after a drop or any non-final close (0.5 s doubling to 10 s, reset after a connection). 4401, 4404, 1008 and a refused handshake (403) are final and reach the webview as `{"kind": "stopped", "reason"}`. A missing token or daemon is retried, since the daemon may simply not be up yet. Each stream owns a `watch` receiver; `events_unsubscribe` and window `Destroyed` drop the sender, and the stream closes with 1000. The project name is checked against the route pattern before it goes into the URL. Rust sends no `Origin`, which the daemon allows (the token still applies). Tauri channels deliver over IPC, and `plugin:__TAURI_CHANNEL__|fetch` is exempt from the ACL (tauri 2.12.4, `webview/mod.rs`), so neither the CSP nor the capability needed a change for them. `getToken()` is gone.
308. **The Rust WebSocket crate** (T20). `tokio-tungstenite` **=0.30.0** (2026-07-11, the latest), with default features off and only `connect`: plain `ws://` to 127.0.0.1, no TLS stack. It needs `tokio` (`macros`, `sync`, `time`; `net` and `rt` for tests), `futures-util` (`sink`) and `serde_json` as direct dependencies; all were already in the lock file through Tauri and are pinned to the locked versions (=1.53.3, =0.3.34, =1.0.154), so the only new crates are tokio-tungstenite and tungstenite.
309. **The folder picker is Tauri's dialog plugin** (T20). The ticket asks for the Tauri folder picker, which is a plugin in Tauri 2: `tauri-plugin-dialog` **=2.8.3** and `@tauri-apps/plugin-dialog` **2.8.3**, exact. 2.8.4 (2026-10-28) was under two weeks old. The capability grants only `dialog:allow-open`. `pickFolder()` lives in `shared/api` so tests mock it at that boundary.
310. **Run events invalidate queries, coalesced** (T20). Envelopes don't carry done/total, so patching would mean re-deriving the daemon's counts; the hook invalidates instead. `run.*`, `integrate` and `policy.decision` invalidate `["projects"]` (list and detail) and the project's tickets; those plus `attempt.*`, `gate.result` and `review.verdict` invalidate its `["runs", name]`. `agent.*` and `log` change nothing on Home, so a busy agent causes no refetches. Invalidations wait 250 ms and go out once, so a burst (a replay, a run finishing) is one refetch. Query keys live in `shared/api/keys.ts`, so the project slice can invalidate run and ticket data without a sideways import. The last `seq` per project is kept in memory, so returning to Home resumes. The shortcut this entry recorded (a first subscription replayed the whole history from `since=0`) is resolved in T32 (313): the stream starts after the REST answer's `latest_seq`.
312. **Home's states** (T20). The project list is mounted only while the daemon status is ok; when the daemon comes back the section remounts and its stale query refetches, so Home recovers with no reload. A project's status is one icon + label, most urgent first: Running, Paused, Needs you, Unknown, No plan yet, Done, Idle. "Needs you" fetches tickets only for projects whose `needs_you` is above 0 and lists Blocked, Awaiting approval and Paused runs once each. The new dialog uses the native `<dialog>` (as the T03 Settings dialog does) and the progress line a native `<progress>`, so neither needs inline styles or a new UI library. `screens-prompt-v0.md` is not in the repository; the screens follow the ticket and the existing tokens in `shared/styles/tokens.css`.
313. **Subscribing from the latest event** (T32 step 0; resolves the shortcut in 310). The app started a project's first stream at `since=0`. Now `ProjectSummary` (so the list and the detail) and `CurrentRun` carry `latest_seq`, the run log's `MAX(id)`, read *before* the rest of the answer. A state read after an event is then never older than the stream's start, and an event written between the REST call and the subscribe is replayed, since replay covers everything after `since`. `useProjectEvents(projects)` takes `{name, latest_seq}` and starts at the larger of that and the last `seq` it saw; the value is read through a ref, so a refetch doesn't restart the stream. A run log that won't open gives `latest_seq` 0, as before. Full history is read only with `GET …/runs/{id}`.
316. **Panel state and the tab it opens on** (T32). `pages/project/model/state.ts` maps the project, current run and spec to one section-8 row. An active run is running, paused (by the user), or paused with `reset_at` (usage limit, "resumes HH:MM", Cancel only). A running `plan` run means "Planner is running". `next_ticket` means Run next / Run all. Otherwise the disabled reason comes from `idle.code`, or "Write a spec first" / "Generate a plan first" when there are no tickets. The tab is chosen once, when the data first arrives, so starting a plan doesn't pull the user off the Spec tab. The Spec tab stays mounted (`forceMount`, hidden), so switching tabs never drops an edit that isn't saved yet.
317. **Disabled controls carry their reason** (T32). `shared/ui` `ReasonButton` disables itself when `reason` is set. The reason is a `title` tooltip on a wrapper (a disabled button gets no pointer events) and the button's accessible description, which is what the tests assert. Native `title` is used rather than a Radix tooltip, whose positioning sets inline styles (CSP `style-src 'self'`).
318. **Spec autosave** (T32). `useSpecAutosave` keeps the text and the last saved `{content, etag}`. One timer runs 1 s after the last change, only while nothing is saving, no conflict is open and the last save didn't fail; Ctrl/Cmd+S saves at once. A 412 opens the conflict bar with the disk version from the error's `current`, and stops saving. **Reload** takes the disk version, and **Keep mine** saves with the disk ETag, only on that click. A failed save shows Error and retries on the next edit or Ctrl+S, not in a loop. Each save writes the new `{content, etag}` into the spec query, so a remount starts from disk, not from the first load. Generate plan is disabled while the spec isn't saved, since the planner reads the file.
319. **Generate plan, Re-plan and failures** (T32). The button is disabled for an empty spec ("Write at least an objective first") and while a draft plan waits for approval (`idle.code == plan_not_approved`), as the ticket asks. With tickets it is **Re-plan**, behind the D4 confirm, which states the planner's rule (unedited drafts are replaced, edited and approved tickets kept); the daemon has no "keep edited" option to ask about. Progress is the plan run's state and its last phase line, refreshed by run events. A plan run ending `blocked`, or a failed `POST`, shows the red bar with the reason and **Retry**. "View log" waits for the Run tab (T22).
320. **Markdown renderer** (T32). `react-markdown` **10.1.0** (2025-03-07, the latest), exact. It builds React elements from an mdast/hast tree, never HTML strings. `skipHtml` drops raw HTML, and `defaultUrlTransform` empties any URL that isn't http(s), mailto, tel or relative (so `javascript:` is gone). Links get `onClick` `preventDefault`, so a spec link can't navigate the webview away from the app (the app has no opener plugin; opening links is left for later). No GFM plugin: tables and task lists render as text. ESLint `no-restricted-syntax` bans `dangerouslySetInnerHTML`, both as a JSX attribute and as an object key.
321. **Settings** (T32). `features/open-settings` became `features/settings` and `pages/project-panel` became `pages/project`, as the ticket names them. "Ready" means an installed, logged-in backend or a saved Anthropic key. The dialog opens by itself only on Home (`firstRun`), and is not closable (Escape is cancelled, Close is disabled with the reason) only while the agents and settings have loaded and nothing is ready. If either fails to load, it can be closed, so a daemon problem is never a trap. A secret is saved by a plain `api.PUT`, not a TanStack mutation, so the value never sits in the mutation cache. The field is cleared before the request resolves, and the status refetches. A secret from an environment variable can't be removed here; Remove says so. General shows the daemon's folders read-only (they come from `config.toml` / `SPOOLHQ_*`). Theme, OS notifications and "keep running when closed" have nowhere to be stored yet and are left out. About shows the version, the daemon's address and the repository URL as copyable text, and has no logs **Open** button: the daemon doesn't expose its logs folder.

449. **Tracker sync state is polled every 15 s, the one polling exception** (T51). Everything else the app shows follows the run event stream; sync runs in the daemon's tracker thread, outside ticket runs, so no event carries it. `entities/tracker`'s `trackerQuery` uses TanStack Query's `refetchInterval`, 15 s only while the last answer had a `kind`, so a project without a tracker is asked once and never polled; the interval lives in the query's observers, so it stops when Home or that project's panel leaves the screen, and doesn't run in the background. The failed tooltip is the CSS-only one (no Radix), and the error is rendered as text, like every daemon string.
453. **The app starts its daemon with `std::process`, not the shell plugin** (T23). The sidecar is the file Tauri copies next to the app's executable, so `current_exe().with_file_name("spoolhq")` finds it in dev and bundles alike; spawning it from Rust needs no new dependency and no capability, and the webview still can't start processes. It runs `serve` with null stdio (logs go to `~/.spoolhq/logs`) and `CREATE_NO_WINDOW` on Windows.
454. **`/api/health` says `"service": "spoolhq"`; any other answer means the port is taken** (T23). The app probes the port with the token before starting anything. `{"status": "ok"}` alone isn't enough: the `fastapi-react` template's own health route says the same. A 200 with both fields is a SpoolHQ daemon (used, nothing started); silence starts the sidecar with 15 s to answer; anything else starts nothing and Home shows "Port <n> is used by another program". The launch state reaches the webview through `daemon_info` (`launch`), so the status poll shows "Starting SpoolHQ…" while the app checks or starts, and the daemon-missing panel adds the log folder when its own daemon failed. A daemon that exits during start fails at once instead of after 15 s.
455. **A daemon the app started gets SIGTERM, then a kill after 5 s, when the app exits** (T23). The one-file binary is a launcher whose child is the daemon; the live check showed SIGKILL on the launcher leaving the child serving on the port, while SIGTERM is passed on and uvicorn shuts down cleanly. SIGTERM is sent with `kill -TERM <pid>` as an argument list, so no `libc` or `nix` dependency. On Windows the kill stays; whether the launcher's child goes with it wasn't checked on Windows (T49 revisits quitting). A daemon the app found running is never stopped. T49 replaces this with background running.
457. **Closing the window hides it while `desktop.keep_running` is on** (T49). The setting lives in `[desktop]` of `~/.spoolhq/config.toml`, next to the port the app already reads there, rather than in a file of the app's own: the daemon validates it (`Settings.desktop`, unknown keys refused like the rest of the file) and saves it (`PUT /api/settings/desktop`), so the webview needs no new permission, and Rust reads it on every close, so a change applies at once. A missing or broken file counts as on: a bad config never turns closing into stopping a run. The window is hidden, not destroyed, so the webview and its event streams stay up and reopening needs no catch-up.
458. **Quit shuts an app-started daemon down over `POST /api/shutdown`, with a kill after 15 s** (T49; replaces 455). A signal can't say "cancel the run": SIGTERM leads to the loop's shutdown path, which leaves runs `interrupted` for recovery. The route cancels each run the way Cancel does, then sets uvicorn's `should_exit` directly (going through `handle_exit` records SIGTERM, which uvicorn re-raises once stopped, so the process would end by signal, not with 0). Rust gives the whole request and exit 15 s, then kills the process group or job anyway, so strays never survive. A daemon the app found running is never asked: quitting leaves it and its runs going, and the tray says so.
459. **The launcher runs in its own process group (Unix) or a kill-on-close Job Object (Windows)** (T49). The one-file binary is a launcher plus the daemon as its child, and the daemon has agents as children; signalling the launcher alone orphaned them (455). `Command::process_group(0)` is std; signals still go through `kill` with an argument list, keeping 455's "no `libc` or `nix`". On Windows `windows-sys` (already in the lockfile, pinned to 0.61.2) creates the job before the spawn and assigns the launcher right after it; the launcher unpacks itself for far longer than that before starting the daemon, so the daemon is always inside (a `shortcut:` comment marks it). The app holds the job's only handle, so even a crash ends the daemon on Windows. The process test runs the test binary itself as a launcher with a child, on every OS.
460. **The quit confirm and the tray status are native and come from Rust** (T49). Quit has to work while the window is hidden and before the webview could answer, so Rust asks `GET /api/projects` for active runs, shows the plugin dialog's native confirm (**Quit** · **Keep running**; closing it keeps running) and polls the same route every 3 s for the status line. Neither needs a capability, and the confirm and status texts are unit-tested in `quit.rs` rather than in Vitest. Left clicks on the icon open the window where the OS reports them (not Linux).
461. **Settings → General has Quit SpoolHQ, the one new webview permission** (T49). On GNOME without an AppIndicator extension there is no tray, and closing only hides the window, so nothing in the app could quit it. `app_quit` (`allow-app-quit`) starts the same quit as the tray's, confirm included; it takes no arguments. A second launch shows the hidden window through `tauri-plugin-single-instance` (pinned 2.5.5; on Linux it brings zbus into the lockfile), registered before any other plugin.
463. **Installers: AppImage, `.deb` and `.rpm`; NSIS; a `.dmg` for macOS arm64 and x86_64** (T50). Tauri 2.12 bundles `deb`, `rpm` and `appimage` on Linux, `nsis` and `msi` on Windows, `app` and `dmg` on macOS (checked 2026-11-23 with `@tauri-apps/cli` 2.12.3). One Windows installer is enough, and NSIS's per-user install needs no admin prompt, so no MSI. GitHub has a standard Intel runner (`macos-26-intel`, next to `macos-26` for arm64; the runner reference, checked 2026-11-23), so x86_64 Macs get their own `.dmg` instead of a universal build, which PyInstaller's one-file sidecar can't make. Linux builds on `ubuntu-latest` like every other job, so the AppImage needs glibc 2.39; an older base waits for a user who needs it. Each job builds the real sidecar first; the bundle check smoke-tests the copy inside the extracted AppImage, the mounted `.dmg` and the silently installed NSIS setup, so a bundler step that broke the PyInstaller binary fails the release.
464. **The updater plugin is registered in Rust only, with `requireSignedVersion` on** (T50). `tauri-plugin-updater` 2.14.1 (the newest 2.x; 3.0 is alpha) is the one new dependency; the capability gets no updater permission, so the webview can't check or install, and T52 adds Rust commands. `requireSignedVersion` refuses an update whose signature doesn't carry the version the feed announces, closing the downgrade a crafted feed could force; the CLI's build signer writes `version:` into the trusted comment (seen in a local build), and no older release exists that it would reject. The CLI also refuses to sign with an empty or non-matching `pubkey`, so until the user's key is in `tauri.conf.json` a dry run passes a throwaway public key through the workflow's `pubkey` input (dry runs only, checked as base64, given to `tauri build --config` as a file); tags always use the file's.
465. **The macOS app is ad-hoc signed** (T50). `bundle.macOS.signingIdentity: "-"`: Apple Silicon refuses to run an app with no signature at all, and the ad-hoc one needs no certificate. It isn't code signing: Gatekeeper still treats the download as unidentified, and `docs/packaging.md` says how to open it. Real signing and notarization come later.
466. **Linux updates go through the AppImage only** (T50). The updater replaces the running AppImage in place; it can't upgrade a package the system's package manager owns. `latest.json` lists the AppImage as `linux-x86_64`, and `.deb` and `.rpm` users install the new package; T52's notice tells them.
469. **The update check runs in Rust; the webview gets two app commands, no updater permission** (T52). Rust reads the feed at launch, once the daemon is up, and every 6 h, and keeps the result; the webview calls `update_status` (`check: true` for Check now) and `update_install`. Their two generated permissions (`allow-update-status`, `allow-update-install`) are the capability's only new entries: they are the app's own commands, taking no URL, key or path, so the webview still can't choose a feed, a key or a file, and the plugin's own permissions stay out (464). `desktop.check_updates` lives next to `keep_running` in `config.toml`, saved through the daemon and read by Rust before every check; off means `Check::Off` without building an updater, so no request. `minimum_version` is read from the feed's raw JSON into the status and not enforced. The webview reads the status every 60 s (memory only, no request; the capability has no event permission to push it), the same polling exception as 449.
470. **Install and restart: verify, ask the daemon, shut down, install** (T52). The update is downloaded and its signature (and signed version) verified first, so a bad download never touches the daemon. Then `GET /api/projects` must answer with no running or paused run, checked right before the shutdown even though the button is already disabled during a run; no answer refuses too, since a busy daemon could hide a run that the shutdown would cancel. A daemon the app started is then shut down with the quit's `POST /api/shutdown` (458) and the update installed; if installing fails, the launcher starts the old daemon again. An external daemon is never stopped. On success the app restarts through `AppHandle::restart`; Windows' installer ends the app itself.
471. **`.deb` and `.rpm` installs are told apart by `APPIMAGE`** (T52). The AppImage runtime sets `APPIMAGE` for the app it starts, and nothing sets it for a packaged install, so a Linux app started without it gets the "Download the new package from the release page" notice and no install button (466). The bundle type compiled into the binary would tell how it was built, not how it was started, and a copied-out AppImage binary can't update itself either.
472. **The dev feed override is debug-only and local-only; the key never changes** (T52). `SPOOLHQ_DEV_UPDATE_FEED` is honoured only when `cfg!(debug_assertions)` and only for `http://127.0.0.1[:port][/path]` (not `localhost`, not `127.0.0.1.example`), so a release build can't be pointed elsewhere by its environment. The updater's `pubkey` builder method is never called, so every build verifies against `tauri.conf.json`'s key; the update tests build a mock app whose config carries a fixture key, with packages signed by it and by a second throwaway key (`fixtures/update/`, public halves and signatures only).
473. **Linux builds on `ubuntu-22.04`, checked for glibc 2.35** (T52). The oldest Ubuntu runner GitHub offers (checked 2026-11-24: 22.04, 24.04, 26.04; `ubuntu-latest` is 26.04), replacing 463's `ubuntu-latest`, so the AppImage runs on Ubuntu 22.04, Debian 12 and Fedora 36 or newer. `scripts/check_glibc.py` fails the build above 2.35: it scans each ELF file for `GLIBC_x.y` names and, for the PyInstaller sidecar, the libraries inside its archive (read with PyInstaller's `CArchiveReader`), since PyInstaller bundles the build host's `libgcc_s` and friends. A byte scan rather than a `.gnu.version_r` parse needs no `readelf` and works on test fixtures; a bundled libc would over-report, which is the safe direction (a `shortcut:` comment marks it).
474. **A release tag must be annotated with a message** (T52). `release.py check-tag` reads the tag's object type and message (`git for-each-ref`) and fails a lightweight tag or an empty message with "Use an annotated tag with release notes: git tag -a v0.1.0 -m "…"": the message is the release notes the app now shows, and a lightweight tag's "message" would be the commit's. The publish job's `SpoolHQ v0.1.0` fallback goes.
475. **`PUT /api/settings/desktop` writes only the keys sent** (T52). With two `[desktop]` keys, a body with one of them would otherwise reset the other to its default. The route writes `model_fields_set` only and merges them onto the current settings; the app still sends both (its generated client types the body as complete).
476. **The app installs rustls's ring provider at launch** (T52). tauri-plugin-updater turns on reqwest's `rustls-no-provider` feature, and Cargo's feature unification gives it to the app's own reqwest too, so since T50 `daemon::Http::default()` panicked at launch ("No rustls crypto provider is configured"); CI never launches the app, and the T52 live check found it. `run` now installs `rustls::crypto::ring::default_provider()` first, the provider the plugin itself installs before a check. `rustls` becomes a direct dependency pinned to the locked 0.23.46 with the features the plugin already enables, so the lockfile only gains the edge (as `windows-sys` in 459). A test builds the daemon client after installing it and fails without.
