# Decisions · Code graph

Graphify and the code map. Listed in [DECISIONS.md](../../DECISIONS.md).

86. **A Graphify code graph is committed in `graphify-out/` for agent context.** Graphify 0.9.92 (`graphifyy` on PyPI, Apache-2.0), installed as a uv tool, not a project dependency. It is built offline from code only (`GRAPHIFY_BACKEND=none graphify extract . --code-only`, then `graphify cluster-only . --no-label`), so no source leaves the machine and no API key is needed; `graphify .` is the assistant-skill form of the same build. `GRAPH_REPORT.md`, `graph.json` and `graph.html` are committed; the cache, `manifest.json` and `.graphify_*` files are ignored (`.graphify_root` holds an absolute local path). The graph is refreshed by hand until T28 adds SpoolHQ's own Graphify support; Graphify's Claude Code hook and generated `CLAUDE.md` block are not installed.
284. **Plan: the code graph ticket is T28** (T28 step 0, 2026-10-31). Two tickets were numbered T27; "Code graph with Graphify" is now T28 in the ticket table and its section. It is on no critical path and the roadmap embed lists no IDs, so nothing else changed; the table still sums to 76 h over 30 tickets.
286. **What Graphify 0.9.92 offers, checked rather than remembered** (T28). From `graphify --help` and trial runs on a scratch repository: `graphify extract <path> --code-only --out DIR` writes everything to `DIR/graphify-out/` (`graph.json`, `manifest.json`, `.graphify_analysis.json`, `.graphify_root`, and the AST cache in `cache/ast/v0.9.92-…/` keyed by content hash), and nothing to `<path>`. A second `extract` into the same `--out` from a different checkout path is incremental ("1 re-extracted, 1 unchanged"), and deleted code shrinks the graph. `--force` skips the cache. `graphify update` has no `--out` (it writes `<path>/graphify-out/`), so SpoolHQ doesn't use it. `graphify cluster-only DIR --no-label --no-viz` writes `DIR/graphify-out/GRAPH_REPORT.md` and no `graph.html`. `graphify --version` prints `graphify 0.9.92`. The ticket's fallback (copy the cache into the worktree and back) isn't needed: Graphify runs with `cwd` and `--out` in SpoolHQ's cache folder.
287. **The code graph: optional, offline, one cache per project** (T28). `services/codegraph/` (no other service imports) finds `graphify` on PATH and reads its version. It is missing → no map and one log note; a version other than the tested 0.9.92 → a warning (`spool agents` shows both). It always runs offline: `GRAPHIFY_BACKEND=none`, `--code-only`, `--no-label`, the agents' environment allowlist (no API keys), argument lists, 120 s per build with the process tree killed on timeout. Its hooks and skill are never installed. The cache is `<workspace>/.spoolhq/codegraph/`: `current.json` names the current `b-<id>/` build and the Graphify version. A refresh copies the build to `tmp-<id>/` and runs `extract` (an update; a full build uses `--force` into an empty folder) and `cluster-only` there. It renames the folder to a new `b-<id>`, then `os.replace`s the pointer, so a crash leaves the previous build in use; leftovers are removed next time. A failed update deletes the cache and rebuilds once; a cache from another version is discarded. An OS file lock (`core/daemon_lock.acquire_lock`) guards the folder; if it is held, that refresh gives no map instead of waiting.
288. **When the map is built** (T28). For the implementer: when its prompt is built (`runloop/prompting.py`), so after the worktree exists and before the first attempt. Before a retry, only if the worktree's `HEAD` moved or it has uncommitted changes (a merge being resolved); otherwise the map is reused. Once Graphify gave no map in a run (missing, failed, timed out), the run doesn't call it again. That means one note, and a hanging Graphify costs one timeout per run, not one per attempt (my choice; the ticket left it open). For the planner: on the project's checkout, read-only, in the daemon's plan jobs; `spool plan generate` without the daemon gets no map. `spool prompt show` doesn't run Graphify, so its prompt has no map. To keep `machine.py` under 500 lines, `implementer_prompt` and `previous_attempt` moved unchanged to `runloop/prompting.py`.
289. **The code map in the prompt** (T28). From `GRAPH_REPORT.md`, the prompt keeps Summary, God Nodes, Surprising Connections, Import Cycles and Communities. It drops the title (it names SpoolHQ's temp folder), the build commit, the navigation list of `Community N` placeholders, knowledge gaps and suggested questions, which tell the agent to run Graphify. The map is the fifth trimmable input of the context pack: its own `<code_map>` block under "Code map", escaped and fenced like the others, filled last, capped by `context.code_map_chars` (default 8,000, 0 to 100,000; 0 turns it off and never runs Graphify). When it is too long, `keep_connected` drops the `### ` communities with the fewest `Nodes (N)` first and notes `[trimmed: kept the 9 most connected of 152 parts]`. The planner's prompt gets the same block, cut to the same cap. The reviewer's doesn't. Every backend gets it, since it is part of the prompt text. On SpoolHQ's own repository, a full build takes 5.6 s and an update 3.3 s, and the 39,504-character summary is cut to 7,731. The opt-in real run (`tests/services/runloop/test_real_code_map.py`, real `claude` 2.1.316, the hello ticket in a repository with a small `shop/` package, 546-character map) gave: with the map, a full build in 0.5 s, then 6 model calls and 18,265 weighted tokens; the same ticket again, an update in 0.3 s, then 6 calls and 16,091 tokens. Without the map (`code_map_chars: 0`): 8 calls and 21,035 tokens. That is one run each on a toy repository, so it is a sanity check, not a measurement.
290. **SpoolHQ never commits a graph** (T28). `graphify-out` is in the integrator's junk folders, so a graph an agent writes in the worktree is left out of the squash commit. SpoolHQ's own repository still commits its graph by hand (decision 86). A ticket SpoolHQ merges here won't carry the agent's `graphify-out/` changes, so after such tickets the graph is rebuilt and committed by hand.
292. **Tracked files in build folders are committed** (T28 follow-up; changes 290). The integrator now leaves a junk-list path out only if the default branch doesn't track it. `tracked_in` (`services/git/integrate.py`) lists main's tree once with `git ls-tree -r` and intersects. A tracked one, such as a modified `graphify-out/graph.json` in a repository that commits its graph, goes into the commit, and an info `log` event (`tracked files in build folders kept in the commit`) lists it. The check is per file. A new file under a tracked `graphify-out/` that main doesn't have yet is still junk. My choice: "tracked" is the file itself, as git defines it; a project that wants new graph files commits them once by hand.
294. **`spool prompt show` says the map is missing** (T28 follow-up). It doesn't run Graphify (that would build the project's cache from a read-only command). It ends its stderr notes with `Code map: not included here (built only during runs).`, unless `context.code_map_chars` is 0. Stdout stays exactly the prompt text.
